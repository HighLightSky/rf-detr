# 比赛镜像构建与提交流程

本文只记录**从改代码到提交评测的常用命令和流程**。细节原理见：

- 封装说明：[比赛提交docker封装说明.md](比赛提交docker封装说明.md)
- 平台提交操作：[比赛镜像提交说明.md](比赛镜像提交说明.md)

> 所有交互命令默认在仓库根目录执行；涉及 `docker build` 的命令切换到 `deploy/` 目录执行。

## 一、改动代码后重新构建镜像

比赛运行时代码全在 `deploy/app/` 下，改完只需重新 `docker build`。

```bash
cd deploy
docker build \
  --platform linux/amd64 \
  --provenance=false \
  --sbom=false \
  -t 镜像名:标签 .
```

要点：

- **最后一个 `.` 是构建上下文，必须放在 `deploy/` 目录下**（Dockerfile 用相对路径 `COPY app /app`）。
- `--platform linux/amd64`：比赛平台要求的架构，不可省。
- `--provenance=false --sbom=false`：**去掉 buildx 默认附加的溯源（attestation）清单**，否则平台拉取会失败。这是本地 Docker 较新（走 buildx）时的一个必要修正项。
- 只改了 `deploy/app/` 时，模型（`deploy/models/*.onnx`）和环境层会被 Docker 缓存复用，构建很快，**无需**重跑资产装配或重导 `environment.yml`。
- 若本机 `docker build` 不认 `--provenance`，改用 `docker buildx build`（参数相同）。

## 二、仅在模型/依赖变化时执行

```bash
# 默认 ONNX 资产
python deploy/prepare_delivery_assets.py

# PyTorch 变体（额外携带 checkpoint、ProtoGuidance 工件和精简 rfdetr 运行时）
python deploy/prepare_delivery_assets.py --include-pytorch-runtime

# 在 Linux x86_64 + NVIDIA GPU 环境导出依赖（改 environment.yml 时才需要）
conda env export --no-builds | sed '/^prefix:/d' > deploy/environment.yml
```

## 三、本地运行验证（模拟评测系统）

```bash
cd deploy
mkdir -p test-input test-output
cp 你的测试图片.jpg test-input/

docker run --rm \
  --gpus '"device=0"' \
  --network none \
  -v "$PWD/test-input:/input:ro" \
  -v "$PWD/test-output:/output" \
  镜像名:标签 \
  --input /input \
  --output /output

cat test-output/result.json
```

`main.py` **只接受赛事定义的 `--input /input --output /output`**，必须生成 `test-output/result.json`（含 `status`、每张图的 `file_name/width/height/run_end_timestamp`、`objects`）。

## 四、宿主机评测与可视化（不进镜像）

可视化脚本在 `src/scripts/`，明确**不打包进镜像**，属于宿主机排查工具。

```bash
# 只算指标
uv run --no-sync python src/scripts/eval_deploy_result.py \
  --result deploy/test-output/result.json \
  --labels <YOLO标签目录>

# 附带可视化（船舶类 0-3 + 发射车类 24）
uv run --no-sync python src/scripts/eval_deploy_result.py \
  --result deploy/test-output/result.json \
  --labels <YOLO标签目录> \
  --images <原图目录> \
  --visualize \
  --vis-dir deploy/test-output/viz
```

可视化需要宿主机上的**标签 `.txt` 与原图**，按 `image_id`（原图文件名去扩展名）匹配；`--vis-classes` 可改绘制类别，默认 `0,1,2,3,24`。

## 五、推送镜像到 ACR

```bash
# 登录（临时凭证，有效期有限；页面上“生成”后复制这条命令）
docker login --username=<用户名> --password=<临时密码> \
  competition-registry.cn-beijing.cr.aliyuncs.com

# 打 tag（tag 用评测系统页面显示的本次 tag，如 trial-v3.0 / v1.0）
docker tag 镜像名:标签 \
  competition-registry.cn-beijing.cr.aliyuncs.com/competition/<队伍号>:<页面tag>

# 推送
docker push competition-registry.cn-beijing.cr.aliyuncs.com/competition/<队伍号>:<页面tag>
```

推送后**必须确认 manifest 是否干净**——用 `docker pull` 本机复现若被禁用，可用 `imagetools inspect`：

```bash
docker buildx imagetools inspect \
  competition-registry.cn-beijing.cr.aliyuncs.com/competition/<队伍号>:<页面tag>
```

正常应**只显示一个 `Platform: linux/amd64`**，**不能出现 `unknown/unknown` 或 `attestation-manifest`**。若出现，说明构建时没有去掉溯源，回到第一步用 `--provenance=false --sbom=false` 重构建并重推。

## 六、提交评测

推送成功后，回到《比赛镜像提交说明.md》流程：登录系统 → 提交评测 → 查看“我的提交记录”中的任务状态与分数。

## 七、常见坑

| 现象 | 原因 | 处理 |
|------|------|------|
| `docker buildx build requires 1 argument` | `docker build` 漏了构建上下文 `.` | 命令结尾加上 `.` |
| 平台报“镜像拉取失败” | 镜像带了 `unknown/unknown` attestation | 用 `--provenance=false --sbom=false` 重构建重推 |
| 拉取仍失败 | 镜像过大（CUDA+PyTorch+模型）下载超时 | 精简 `environment.yml`（纯 ONNX 可不放 PyTorch）；确认 `models/` 只放必需权重 |
| `同一个 tag 不允许重复提交` | 该 tag 已提交过 | 换页面显示的新 tag 再推再提交 |
| 容器跑不出 `result.json` | `main.py` 只认 `--input/--output`；额外参数会被拒绝 | 用第三步的标准 `docker run` 命令，别加额外参数 |
