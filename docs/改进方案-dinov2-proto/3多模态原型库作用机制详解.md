## 0. 核心结论

多模态原型库是**只读的锚**：它的参数（`P_v`、`P_t`）从加载那一刻起冻结，不随训练更新；
它**不产生任何独立的输出分支**，全部影响都通过"与它的相似度"传导进主检测路径的两个位置：

```text
作用点 1（位置）：token 与融合原型的余弦相似度 → 残差合并进 top-k 选择分数
                 → 改变"哪些 encoder token 变成 decoder query"（召回入口）

作用点 2（内容）：选中 query 按关联类别对原型做槽位交叉注意力 → gate 残差
                 → 给 decoder content query 注入类别先验（判别偏置）

作用点 3（监督）：proto_logits 的类别均衡 CE（只算 matched foreground）
                 → 梯度直达融合模块与投影，保证作用点 1/2 的"锚"语义正确
```

每次前向中，原型库被访问 **5 次**（融合重算 1 次、位置打分 1 次、内容增强 1 次、
辅助损失 1 次、监控 1 次），全部在 [transformer.py](../../src/rfdetr/models/transformer.py)
的 two-stage query selection 前后完成，decoder 内部不再触碰原型。

## 1. 全景：一次前向里原型库的完整时序

```text
transformer.forward（two-stage 路径）
│
├─① fused_prototypes()            ← 重算融合原型（可学习权重，每步都要最新）
│    P_mm [25, 10, 256]（逐槽位 L2 归一化，无效槽位置零）
│
├─② position_score(output_memory) ← 逐 token 打分
│    token_h = normalize(proj_token(mem))          [bs, N, 256]
│    sim     = token_h · P_mm^T                    [bs, N, 25, 10]（逐槽位余弦）
│    class_sim = max over slots                    [bs, N, 25]
│    proto_logits  = class_sim / tau_p             [bs, N, 25]
│    proto_score   = 目标类 max − 竞争类 max（margin）  [bs, N]
│    selected_class= argmax class_sim              [bs, N]
│
├─③ calibrate_position_score(proto_score, linear_score)
│    margin 居中 → 缩放到线性 objectness 的 std × 0.1
│
├─④ select_score = linear_score + λ_eff·校准后 margin
│    topk(select_score)                            ← 位置引导在此生效
│
├─⑤ 记录选中 query 的 proto_logits/selected_class/confidence（gather 自 top-k 索引）
│
├─⑥ enhance_content(tgt[:ts_len], selected_class, confidence)  ← 内容引导在此生效
│    ctx = 槽位交叉注意力 softmax((tgt·P^T)/√d) @ P_mm[selected_class]
│    gate = sigmoid(MLP([tgt, ctx])) × 原型置信度
│    tgt' = tgt + γ_eff · gate · ctx
│
└─⑦ （训练时）collect_stats(...) → monitor；loss_proto_labels ← 辅助监督
```

其中 ①②③④⑤ 在 [transformer.py:389-418](../../src/rfdetr/models/transformer.py#L389-L418)，
⑥ 在 [transformer.py:528-557](../../src/rfdetr/models/transformer.py#L528-L557)。

## 2. 逐步详述

### 2.1 融合原型重算（每次前向都做）

```python
def fused_prototypes(self):      # guidance.py:267-281
    return self.fusion(self.visual_bank.prototypes, self.P_t_clip, self.visual_bank.slot_valid_mask)
```

`fusion` 内的 `w_v/w_t/proj_v/proj_t` 都是可学习参数，因此**融合原型不能缓存**——每个前向
必须用最新权重重新融合、重新归一化（见 2文本原型与视觉原型对齐详解 §5）。产物形状 `[25, 10, 256]`，
逐槽位单位向量，无效槽位（少样本类缺形态）为零向量。

### 2.2 位置打分：token 与原型库的相似度

[guidance.py:293-336](../../src/rfdetr/sscl/proto_guidance/guidance.py#L293-L336)：

- 每个 encoder token 经 `proj_token` 投影、L2 归一化，与全部 `[25, 10, 256]` 融合原型做
  逐槽位余弦 → `[bs, N, 25, 10]`；
- **槽位维取 max**：每个 token 只认"25 类里最像的那个类的那个形态"——类内多形态不互相拖累；
- `proto_logits = class_sim / tau_p`：tau_p=0.2 把余弦放大到 [-5, 5] 的 logits 区间；
- `proto_score` = margin：目标类最高相似度减去最强竞争类相似度。有 `target_classes`
  时只对目标类取 max（聚焦舰船易混类），否则全局 top1−top2；
- `selected_class` = 相似度 argmax——它是内容增强的"关联类别"来源。

### 2.3 分数校准：防止尺度错位

[guidance.py:345-352](../../src/rfdetr/sscl/proto_guidance/guidance.py#L345-L352)：

```text
margin 居中（减均值）
→ 除以 margin 的 std（自身归一）
→ 乘线性 objectness 的 std × POSITION_SCORE_STD_RATIO(0.1)
```

原型 margin 与线性 objectness 不在同一尺度上，直接相加会让某一方主导 top-k。
校准后 `λ·proto_score` 的注入量约为线性分数的 10% 量级——**给原始 objectness 留出稳定主干**，
原型分数只做边际修正。监控里的 `lambda_effective` 指标就是按实际注入后的标准差比例计算的。

### 2.4 合并与 top-k：位置引导生效点

```text
select_score = linear_score + λ_eff · calibrated_proto_score
```

- λ_eff 由 warmup 调度（`current_epoch / warmup_epochs` 线性插值，init 0.05 → max），
  关闭时 λ=0 数学恒等于原版；
- **residual 形式**：不替换线性分数，只改变排序。效果是某些"线性分低但像原型"的 token
  挤进 top-k，另一些"线性分高但不像任何目标类"的 token 被挤出；
- top-k 索引变化 → gather 出的 proposal box/refpoint 变化 → **position query 的来源被改变**。
  这就是"位置增强"的全部含义：不碰坐标、不碰特征，只换人。

### 2.5 记录选中 query 的原型信息

top-k 后按选中索引 gather：`proto_logits_ts [bs, Q, 25]`、`selected_class_ts [bs, Q]`、
`proto_confidence_ts [bs, Q]`、`linear_logits_ts`、`topk/linear_topk` 索引对
（[transformer.py:431-460](../../src/rfdetr/models/transformer.py#L431-L460)）——
这些是内容增强、辅助损失、监控三者的共同输入。

### 2.6 内容增强：选中 query 与原型库的第二次交互

[guidance.py:354-384](../../src/rfdetr/sscl/proto_guidance/guidance.py#L354-L384)：

1. 每个选中 query 按其 `selected_class` 取该类 10 个槽位原型；
2. **槽位交叉注意力**：`ctx = softmax((tgt·P^T)/√d) @ P`（[fusion.py:165-183](../../src/rfdetr/sscl/proto_guidance/fusion.py#L165-L183)）
   ——query 按自身外观对 10 个形态加权聚合，得到"该类最贴合的上下文"；全无效槽位退回均匀注意力；
3. **gate**：`sigmoid(MLP([tgt, ctx]))`，bias 初始 logit(0.05)≈-2.944（初始 gate≈0.05 保留梯度），
   再乘原型分类置信度 `class_confidence(proto_logits)`（softmax max 概率去均匀项）——低置信度时削弱注入；
4. **残差注入**：`tgt' = tgt + γ_eff·gate·ctx`，γ 同样走 warmup。

只作用于 two-stage 选中的 tgt 前段，尾部原始 query 不动。decoder 拿到的是
"位置 + 类别先验"的 query——这是"内容增强"的全部含义。

### 2.7 辅助损失：把语义锚钉进梯度

`pred_proto_logits` 挂在 enc 分支输出上（[lwdetr.py:725-733](../../src/rfdetr/models/lwdetr.py#L725-L733)），
criterion 对它做类别均衡 CE（[criterion.py:566-603](../../src/rfdetr/models/criterion.py#L566-L603)）：

- 只用 **Hungarian matched foreground**，未匹配 query 不参与（背景 query 远多于前景，
  全量参与会让打分分支塌缩成"全部低分"）；
- 各类独立求均值再平均（防高频类吞梯度）；
- 梯度路径：`proto_logits → P_mm → fusion(proj_v/proj_t/w_v/w_t) → proj_token`——
  **融合模块和投影的全部参数都获得直接监督**（见 2文本原型与视觉原型对齐详解 §6）。

### 2.8 监控：判断原型库是否真在起作用

`collect_stats`（[guidance.py:429-498](../../src/rfdetr/sscl/proto_guidance/guidance.py#L429-L498)）
每步输出（经 [monitor.py](../../src/rfdetr/sscl/proto_guidance/monitor.py) 聚合进 tensorboard）：

| 指标 | 含义 | 健康标志 |
| --- | --- | --- |
| `topk_overlap` | 合并分数与纯线性分数的 top-k 交集比例 | <0.95 且持续下行（否则位置分支 no-op） |
| `proto_selected_ratio` | 被原型残差新带入 top-k 的比例 | >0.05（与 overlap 互补） |
| `lambda_effective` | 实际注入强度（含校准比例） | 随 warmup 上升 |
| `proto_logits_pmax_mean / entropy_mean` | 选中 query 原型分类的锐度 | pmax 上升 / entropy 下降 |
| `proto_margin_mean` | 目标类与竞争类的相似度差 | 上升（类间分离） |
| `prototype_*`（geometry） | 融合原型的类间余弦/有效秩 | 类间分离、无塌缩 |
| `selected_class_hist` | 选中 query 的类别分布 | 与 GT 分布近似（否则选择有偏） |
| `gate_mean` | 内容 gate 均值 | 不应长期为 0（内容分支 no-op） |

## 3. 开关语义与恒等性（防 no-op 的三道闸）

| 开关 | 关闭时 | 恒等性 |
| --- | --- | --- |
| `position_enabled: false` | select_score = linear_score，① 不参与排序 | 完全恒等 |
| `content_enabled: false` | enhance_content 原样返回 tgt | 完全恒等 |
| `aux_loss_enabled: false` | 不产生 loss_proto_labels | 主损失不变 |
| λ/γ warmup 早期（0.05） | 注入量接近 0 | 渐进式生效 |

模块加载失败（产物缺失/形状不符）→ 整个 `ProtoGuidance` 不挂载，全部位置恒等短路。
这正是 E0 baseline 与各开关消融可以直接对比的原因。

## 4. 训练与推理的差异

| 环节 | 训练 | 推理 |
| --- | --- | --- |
| fused_prototypes | 每步重算（权重在更新） | 重算（权重冻结） |
| collect_stats / monitor | 每 N 步采样聚合 | 不执行 |
| loss_proto_labels | 参与反向 | 不执行 |
| group_detr | >1 组时逐组打分再拼接 | group=1 |
| selected_class 等张量 | 供增强/损失/监控 | 仅内容增强使用 |

推理路径与训练共享 ①②③④⑤⑥，但 ⑦ 与监控被跳过——**原型库在推理时零额外损失开销**，
只有融合重算 + 打分 + 增强三次前向调用。

---

## 5. 一句话总结作用方式

原型库**不生产任何独立预测**，它只做三件事：① 用相似度给 top-k 选择"换人"（召回入口）；
② 用槽位注意力给选中 query "带类别先验进 decoder"（判别偏置）；③ 用辅助损失把"锚的语义"
钉进可学习投影的参数里（保证①②不漂移）。监控指标是判断它是否真在干活的唯一依据——
`topk_overlap` 不降、`gate_mean` 恒 0、`lambda_effective` 不升，都意味着模块在 no-op。
