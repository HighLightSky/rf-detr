## 0. 核心结论（四问速答）

| 问题 | 结论 |
| --- | --- |
| 视觉原型如何构建？ | 在 **backbone/projector 的 P4 特征图**上，按 **GT 框区域做均值池化**提取每类实例特征，再对每类做**余弦 k-means** 聚类成 M=10 个槽位子原型 |
| 用的是之前的 120 轮微调 ckpt 吗？ | **是**：`output/0813-SHWX-rfdetr-medium-baseline-精细标注/checkpoint_best_total.pth`（120ep 全量微调 baseline；实测元数据 `best_total_source='regular'`，即该 run 的 EMA 未胜出，best-total 存的是 regular 权重） |
| 从哪一层得到视觉特征？ | **backbone 输出**（不经 transformer encoder）：DINOv2（windowed-small、patch 16、取 block 3/6/9/12 四层输出）→ MultiScaleProjector 的 **P4 尺度** → C2f + LayerNorm → `[B, 256, 40, 40]`（640 输入） |
| 视觉特征如何保存？ | 聚类后存入 `data/proto_guidance_shwx.pt`（`torch.save` dict）：`visual_prototypes [25, 10, 256]` + `valid_slots [25, 10]`（bool）+ `text_prototypes [25, 768]` + `class_names` + `meta`，detach 到 CPU 保存，训练时 `copy_` 进 buffer 冻结使用 |

## 1. 构建流程全景

```text
SHWX-dataset-dict-redo 训练集（YOLO）
    ↓ RFDETRDataModule（与训练同分布：AERIAL 增强、mosaic=0、multi_scale=false、640）
加载 0813 120ep baseline checkpoint 的 RFDETRMedium（eval + no_grad）
    ↓ net.backbone(samples)
P4 特征图 [B, 256, H, W]（DINOv2 → MultiScaleProjector，H=W=640/16=40）
    ↓ 逐图、逐 GT 框：归一化 xywh → 特征图坐标 → 框内区域均值池化
每类实例特征列表 features_by_class[c] = [N_c, 256]
    ↓ 每类独立做余弦 k-means（k = min(10, N_c)，20 轮）
visual_prototypes [25, 10, 256] + valid_slots [25, 10]（实例不足的槽位置无效）
    ↓ 与 CLIP 文本原型 [25, 768] 一起 save_proto_artifacts
data/proto_guidance_shwx.pt
```

## 2. 使用的 checkpoint（Q2 详答）

**是，且必须是与训练侧同源的 backbone 权重。** 脚本硬编码（[stage0_build_proto_guidance.py:49-51](../../src/scripts/semantic_experiments/stage0_build_proto_guidance.py#L49-L51)）：

```python
BASE_CHECKPOINT = str(
    Path("output/0813-SHWX-rfdetr-medium-baseline-精细标注/checkpoint_best_total.pth").resolve()
)
```

要点：

- **为什么是这个 ckpt**：视觉原型要服务的位置打分/内容注入发生在 RF-DETR hidden space，原型必须来自"已适配 SHWX 的骨干/projector 特征空间"。0813 baseline 是 120ep 全量微调产物，E 系列全部实验的 `pretrain_weights` 也指向它——**原型空间、E 系列训练起点、训练时 token 打分输入三者同源**，保证空间一致。
- **权重来源**：该 run `use_ema=true`，但实测 checkpoint 元数据 `best_total_source='regular'`——即 EMA 未以严格大于规则胜出，`checkpoint_best_total.pth` 里存的是 regular（非 EMA）权重。不要想当然地把它当 EMA 权重。
- **两处口径注意**：
  - 脚本 docstring 第 16 行写的是 "pretrain_weights=0805 checkpoint"，**这是过时注释**，实际代码（BASE_CHECKPOINT）是 0813；
  - 0813 baseline 本身是用 `SHWX-dataset-dict`（旧标注）训练的，而特征提取用 `-redo`（新标注）数据——特征空间由 ckpt 权重决定，数据只影响"抽样哪些实例"，两者不冲突，但重建原型或更换 ckpt 时要保持记录清晰。

## 3. 从哪一层提取特征（Q3 详答）

`net.backbone(samples)` 的输出（[stage0_build_proto_guidance.py:142-143](../../src/scripts/semantic_experiments/stage0_build_proto_guidance.py#L142-L143)）：

```python
features, _, _ = net.backbone(samples)
feat = features[0].tensors  # [B, 256, H, W]（P4 单尺度）
```

具体层级链（[backbone.py](../../src/rfdetr/models/backbone/backbone.py)）：

```text
输入 640×640
  ↓ DINOv2（encoder: "dinov2_windowed_small"，patch_size=16，out_feature_indexes=[3,6,9,12]，windowed attention）
4 层特征（block 3/6/9/12 输出，分辨率均为 40×40）
  ↓ MultiScaleProjector（projector_scale=["P4"]）
P4 尺度 = scale factor 1.0 = DINOv2 原生输出分辨率（不做上/下采样）
  ↓ 通道拼接 → C2f → LayerNorm
  → [B, 256, 40, 40]（hidden_dim=256，为 RF-DETR transformer 的消费维度）
```

关键点：

1. **这是 transformer encoder 的输入特征，不是 encoder 输出**。脚本直接调用 `net.backbone`，绕过了 encoder 的 self-attention 与 `enc_output` 投影。原因：视觉原型要与训练时 token 打分（`proj_token` 的输入）对齐，而离线冻结的是"骨干适配后的特征空间"；encoder 输出随训练漂移，不能作为离线锚。
2. **为什么 P4 单尺度**：medium 变体默认 `projector_scale=["P4"]`，训练时 encoder token 只有这一个尺度。原型与打分 token 必须同分辨率同语义粒度。
3. **patch_size=16** → 640 输入对应 40×40 特征图；GT 框坐标在此网格上换算（见下节）。若以 1024 训练（joint120 实验），特征图为 64×64，但特征空间不变。

## 4. 实例特征提取细节（Q1 前半）

数据与模型配置与训练侧保持一致（[stage0_build_proto_guidance.py:122-133](../../src/scripts/semantic_experiments/stage0_build_proto_guidance.py#L122-L133)）：

- `RFDETRDataModule` 构建训练集 DataLoader：`SHWX-dataset-dict-redo`、YOLO 布局、AERIAL 增强、`mosaic_p=0.0`、`multi_scale=false`、分辨率 640——**与 E 系列训练数据分布相同**；
- 模型 `eval()` + `no_grad()`，逐 batch 前向 `net.backbone` 拿 P4 特征图。

每张图每个 GT 框的提取（[stage0_build_proto_guidance.py:145-163](../../src/scripts/semantic_experiments/stage0_build_proto_guidance.py#L145-L163)）：

```python
# box 是归一化 xywh（中心点 + 宽高）
x0 = max(int((cx - bw / 2) * w), 0)
y0 = max(int((cy - bh / 2) * h), 0)
x1 = min(int((cx + bw / 2) * w) + 1, w)
y1 = min(int((cy + bh / 2) * h) + 1, h)
region = img_feat[:, y0:y1, x0:x1]
features_by_class[class_id].append(region.mean(dim=(1, 2)))  # [256]
```

- **"masked average pooling"的真实语义**：以 GT 框区域为 mask，对框内全部特征位置取空间均值——无参数、无学习型 RoI 头，一个框产出 1 个实例特征向量；
- 坐标换算：归一化 xywh 直接乘以特征图宽高（`w, h`），越界 clamp、空框跳过；
- 类别语义由 GT label 决定，天然无监督聚类之外的强先验——**实例特征永远带真值标签**。

## 5. 余弦 k-means 聚类与槽位（Q1 后半）

每类独立聚类（[stage0_build_proto_guidance.py:72-106](../../src/scripts/semantic_experiments/stage0_build_proto_guidance.py#L72-L106)）：

```text
k = min(NUM_SLOTS=10, N_c)            # 实例不足 10 个的类，槽位数=实例数
初始化：randperm 均匀抽样 k 个实例作中心（注释声称固定种子可复现，见下方注意）
迭代 20 轮：
    sim = normalize(features) @ normalize(centers).T   # 余弦相似度分配
    每簇中心 = 簇内特征均值
valid_slots：实际聚类出的槽位置 True，其余 False（零向量）
```

- **为什么余弦 k-means 而不是欧氏 k-means**：与在线打分 `cosine / tau_p`（[guidance.py:301-317](../../src/rfdetr/sscl/proto_guidance/guidance.py#L301-L317)）同度量——聚类空间 = 打分空间，避免欧氏聚类出的中心在余弦度量下不可用；
- **槽位语义 = 类内多形态**：每类 M=10 个子原型表达"同类不同形态"（舰船不同角度/尺度、飞机不同机位）。在线打分时对槽位维取 max（只认最像的那个子形态），内容增强时做槽位交叉注意力（按 query 自身外观加权聚合各子形态）；
- **少样本类**：实例不足的类（如 HM 训练集样本极少）槽位数 = 实例数，剩余槽位置无效；极端无实例的类全部无效，打分时该类被排除；
- ⚠️ **注意**：`_cluster_slots` 内注释写"随机种子固定，产物可复现"，但脚本中没有 `torch.manual_seed` 调用——严格意义上产物不可复现。若需要确定性重建，应先固定全局随机种子。

## 6. 保存格式与加载链路（Q4 详答）

`save_proto_artifacts`（[artifacts.py:29-61](../../src/rfdetr/sscl/proto_guidance/artifacts.py#L29-L61)）写入 `data/proto_guidance_shwx.pt`：

| 键 | 形状/类型 | 说明 |
| --- | --- | --- |
| `visual_prototypes` | `[25, 10, 256]` float32 | 聚类中心，**未归一化**（融合时在 SimpleProtoFusion 内做 L2 normalize），detach 到 CPU |
| `valid_slots` | `[25, 10]` bool | 槽位有效掩码 |
| `text_prototypes` | `[25, 768]` | CLIP 文本原型（多提示词平均，未投影、不归一化） |
| `class_names` | `list[str]` ×25 | 类别名 |
| `meta` | dict | `dataset=shwx`、`num_classes`、`hidden_dim=256`、`text_dim=768`、`num_slots=10`、`resolution=640`、`checkpoint`（绝对路径）、`cluster_iters=20`、`note` |

训练时加载链路（[guidance.py:216-262](../../src/rfdetr/sscl/proto_guidance/guidance.py#L216-L262)）：

```text
ProtoGuidance.build(artifacts_path)
  → load_proto_artifacts（FileNotFound / 缺键检查）
  → validate_proto_artifacts（形状、NaN 校验；dataset 元信息不匹配仅警告）
  → copy_ 进 SlotPrototypeBank 的 register_buffer（prototypes / slot_valid_mask / slot_num_updates）
  → copy_ 进 P_t_clip buffer
  → 整个训练期冻结不更新（visual_ema_update 默认关闭）
```

任何校验失败 → 记 warning 并返回 `None`，模块不挂载，训练/推理数学恒等于原版（优雅降级）。

## 7. 与在线模块的空间对齐（拓展）

视觉原型本身冻结，但它不直接参与打分——中间隔着可学习投影（[fusion.py:29-102](../../src/rfdetr/sscl/proto_guidance/fusion.py#L29-L102)）：

```text
P_mm = normalize(softplus(w_v)·proj_v(P_v) + softplus(w_t)·proj_t(P_t))
token_h = normalize(proj_token(encoder_output_memory))
proto_logits = token_h · P_mm^T / tau_p        # 位置打分
```

- `proj_v`：视觉原型 → 融合空间；`proj_t`：CLIP 文本 → 融合空间；`proj_token`：encoder token → 融合空间——**三者共同学习对齐**，原型本身冻结是锚；
- 融合权重初始 `w_v=0.3 / w_t=0.7` 故意偏向文本：少样本类视觉原型噪声大，CLIP 文本作早期稳定锚；
- 这是"离线锚 + 在线投影"的解耦设计：原型不必随训练漂移，投影负责适配。

## 8. 与训练实验的关系、局限与改进方向（拓展）

1. **联合训练（joint120）后的特征漂移**：joint120 从零共适应 120ep，backbone/encoder 特征空间会偏离 0813 的锚空间；在线投影 + 辅助损失会拉着 `proj_token` 向旧原型对齐（辅助损失是唯一直接监督），但这是"学习适应旧锚"，不是"锚跟着新特征走"。若联合训练显著改变特征空间，可选方向：用 joint120 的 ckpt 重建原型产物（脚本 `BASE_CHECKPOINT` 换成 joint120 的 `checkpoint_best_total.pth`），再跑阶段二。
2. **分辨率口径**：产物在 640 下提取（40×40 网格），而 joint120/20 实验用 1024 训练（64×64 网格）——特征空间不变，但每个 GT 框覆盖的 patch 数约为 2.56 倍，1024 下的实例特征细节更丰富。若以 1024 长期训练，重建产物能获得更细的原型。
3. **为什么不做成在线 EMA 更新**：`visual_ema_update` 接口已实现（[guidance.py:386-424](../../src/rfdetr/sscl/proto_guidance/guidance.py#L386-L424)）但 v1 默认关闭。原因：训练期用 GT 框 EMA 更新原型会让"锚"跟随训练分布，且与 CLIP 文本原型的融合语义会漂移；先验证冻结锚的有效性，再考虑放开。
4. **与 SSCL 原型的关系**：SSCL prototype 模式（当前 E 系列关闭）的视觉原型来自 decoder 最后一层 matched query 特征，与本文档的 backbone P4 空间**不是同一空间**——两者类别索引/语义对齐，但向量不可直接比较（见方案设计文档 §1.4）。
