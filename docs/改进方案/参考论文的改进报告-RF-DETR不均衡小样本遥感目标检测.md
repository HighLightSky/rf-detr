# RF-DETR 不均衡小样本遥感目标检测改进报告

## 1. 任务理解与方案定位

本赛题的本质不是在常规数据充分场景中追求更高 mAP，而是在新发射卫星或新观测区域投入运行初期，仅依赖少量、类别高度不均衡的在轨样本，快速构建稳定、高召回、低虚警、可工程部署的光学遥感时敏目标检测模型。评分文件明确给出了三项硬门槛：整体召回率不低于 85%，虚警率不高于 20%，单幅 10000x10000 图像在 RTX3090 或同等算力设备上推理不超过 20 秒。初赛三类目标合并计算整体指标，但评分还会参考舰船、飞机、车辆三类各自的召回率和虚警率，因此方案不能只照顾大目标，也不能牺牲车辆等小目标。

RF-DETR 是合适的主干框架：它以 DINOv2 视觉骨干、轻量 DETR 解码器、IoU-aware BCE 分类损失和端到端检测流程为基础，在实时检测中具备较强的精度和速度平衡。RF-DETR 论文中的 NAS 搜索没有在当前开源代码中完整开放，本项目也不计划依赖 NAS。因此，本方案将 RF-DETR 视为一个强实时检测基座，围绕小样本、类别不均衡、遥感小目标和超大图推理四个痛点进行可控改造。

建议将最终作品包装为 **SGS-RF-DETR：语义引导的稀疏小样本 RF-DETR**。其中 SGS 表示 Semantic-guided Sparse few-shot learning。核心故事是：用文本语义与基类原型缓解新类样本不足和类别不均衡，用遥感专用增强与参数高效微调提升少样本泛化，用全局到局部的稀疏切片推理满足 10000x10000 大图 20 秒约束。

## 2. 总体技术路线

推荐主线由三个模块组成。

1. **语义引导检测头**：引入轻量文本语义分支，但不在推理时运行重型 CLIP。训练前离线用 CLIP 文本编码器将类别名称、别名和遥感描述提示词编码为文本原型；训练时把这些文本原型投影到 RF-DETR 的解码器特征空间，用作分类头初始化、语义蒸馏和相似类对比约束；推理时只保留一个小型投影层和类别原型矩阵，几乎不增加延迟。

2. **基类到新类的原型迁移库**：在基类训练阶段，从匈牙利匹配后的正样本 query 特征中维护类别原型和尺度子原型；进入小样本微调时，使用文本语义相似度从基类原型加权合成新类初始原型，再用少量在轨样本进行 EMA 校准。这样新类不是从随机分类权重开始学习，而是从“语义相近、视觉相近”的基类知识中继承。

3. **超大图稀疏推理流水线**：借鉴 UHR-DETR 的全局到局部思想，先在低分辨率全图上预测目标区域 Gain Map，再用软抑制贪心策略选择有限数量的高价值局部切片，最后批量送入 RF-DETR Small 或 Medium 进行高分辨率检测。对可能漏掉的孤立目标保留低成本兜底策略，确保召回优先，同时通过 TensorRT FP16、批量切片和坐标级去重控制 20 秒时限。

三者对应赛题痛点如下。

| 赛题痛点 | 对应设计 | 作用 |
| --- | --- | --- |
| 少量样本 | 文本原型、基类原型、新类原型初始化、LoRA 微调 | 减少从零学习类别边界的需求 |
| 类别不均衡 | 类别均衡采样、少数类 Copy-Paste、原型重加权、语义对比损失 | 抑制多数类偏置，提升稀有类召回 |
| 目标尺度不一和小目标 | P3 多尺度特征、局部高分辨率切片、小目标增强 | 保留车辆等小目标细节 |
| 10000x10000 推理 20 秒 | Gain Map 稀疏选片、批量推理、TensorRT FP16、动态切片预算 | 避免全图密集滑窗导致超时 |
| 新卫星或新区域域偏移 | 遥感成像增强、风格和辐射扰动、参数高效微调 | 提高跨轨道、跨区域泛化 |

## 3. RF-DETR 基线分析

当前开源代码中，RF-DETR 的核心检测模型在 `src/rfdetr/models/lwdetr.py`。`LWDETR` 使用 DINOv2 backbone 和 `Transformer` 解码器，检测头由 `class_embed = nn.Linear(hidden_dim, num_classes)` 与 `bbox_embed = MLP(...)` 组成。默认 query 数为 300，训练时通过 GroupDETR 扩展为多个 query 组以加速收敛，推理时只保留实际 query 数。

配置集中在 `src/rfdetr/config.py`。`RFDETRSmallConfig` 默认使用 `dinov2_windowed_small`、输入分辨率 512、patch size 16、3 层 decoder、300 queries 和 `projector_scale=["P4"]`。`RFDETRMediumConfig` 分辨率提高到 576，decoder 增至 4 层。对于比赛，默认建议以 `RFDETRSmall` 起步：它速度余量更好，适合大图批量切片；若车辆召回不足，再在局部检测阶段尝试 `RFDETRMedium` 或提高输入分辨率。

RF-DETR 已有若干对本项目有用的能力。

| 能力 | 代码位置或配置 | 用法 |
| --- | --- | --- |
| DINOv2 预训练 | `encoder="dinov2_windowed_small"` | 提供强视觉先验，适合小样本迁移 |
| LoRA | `backbone_lora=True` | 小样本微调时减少可训练参数 |
| 冻结编码器 | `freeze_encoder=True` | 先训练头部和原型，防止破坏预训练特征 |
| 多尺度训练 | `multi_scale=True`, `expanded_scales=True` | 适配不同 GSD 与尺度变化 |
| EMA | `use_ema=True` | 提升小样本训练稳定性 |
| IoU-aware BCE | `ia_bce_loss=True` | 分类分数包含框质量信息，有助于控虚警 |
| P3/P4/P5 投影 | `projector_scale` | 可为小目标引入更高分辨率特征 |

本方案尽量沿用这些能力，只在分类头、损失、数据采样和推理流水线上做增量改造，避免把 RF-DETR 改成另一个复杂系统。

## 4. 改进一：轻量文本语义分支

### 4.1 为什么文本分支应作为主线

小样本检测失败的关键常常不是定位框回归，而是类别判别边界不稳定。舰船、车辆、飞机在遥感视角下存在高类内变化和高类间相似，例如车辆与小型装备、船舶与港区设施、飞机与机场背景结构容易混淆。纯视觉检测头需要从很少样本中学习类别权重，容易被多数类牵引。文本语义可以提供类别之间的先验关系，尤其是在新类样本很少时，让分类头不完全依赖少量视觉样本。

但不能直接采用 GroundingDINO 或在线 CLIP 这种重型开放词表检测思路。比赛有 20 秒大图推理约束，在线文本编码器和跨模态大模型会拖慢局部切片批处理。因此建议采用“训练期重、推理期轻”的设计。

### 4.2 文本原型构建

对每个类别构建多提示词集合，例如：

| 类别 | 示例提示词 |
| --- | --- |
| 舰船 | `a satellite photo of a ship`, `an overhead optical remote sensing image of a vessel`, `a small ship in harbor or river` |
| 飞机 | `a satellite photo of an airplane`, `an aircraft parked on airport apron`, `an overhead remote sensing image of a plane` |
| 车辆 | `a satellite photo of a vehicle`, `small vehicles on road or parking area`, `overhead optical image of cars and trucks` |

如果数据集中有更细粒度类别，比如运输车、坦克、油罐车、快艇、客机，可以先为细粒度类别生成文本原型，再在提交时映射到舰船、飞机、车辆三大类。文本原型离线生成并保存为 `class_text_prototypes.pt`，训练和推理只读取张量。

设 RF-DETR decoder 输出的 query 特征为 `h_i`，类别文本原型为 `t_c`，增加一个轻量投影层：

```text
z_i = normalize(W_v h_i)
e_c = normalize(W_t t_c)
logit_text(i, c) = s * z_i dot e_c
logit_final = logit_visual + lambda_text * logit_text
```

其中 `logit_visual` 是原有线性分类头输出，`logit_text` 是余弦相似度分类分支。推理时 `e_c` 已预计算，额外开销只是一次小矩阵乘法。

### 4.3 语义蒸馏与相似类约束

训练时，针对匈牙利匹配到 GT 的正样本 query，加入两个辅助损失。

1. **文本对齐损失**：让 query 特征靠近对应类别文本原型。它不替代原有检测损失，只作为辅助正则项。

2. **语义加权监督对比损失**：借鉴 SCG-FSOD 的思想，用 CLIP 文本原型计算类别相似度矩阵。语义上越相似的负类，在对比损失中权重越大，使模型重点拉开容易混淆的类别。例如舰船和港口设施、车辆和小型装备、飞机和机场结构应被更强地区分。

建议损失组合为：

```text
L = L_det + alpha * L_text_align + beta * L_semantic_contrast + gamma * L_proto
```

初始建议：`alpha=0.05`，`beta=0.05`，`gamma=0.1`。若发现分类召回下降，先减小 `beta`，保留文本原型初始化和轻量融合。

### 4.4 工程落点

推荐新增 `SemanticCosineClassifier`，替换或包裹 `LWDETR.class_embed`。不要一开始删除原线性头，而是采用视觉线性头加文本余弦头的残差融合，便于做消融并降低风险。

涉及文件：

| 模块 | 建议改动 |
| --- | --- |
| `src/rfdetr/models/lwdetr.py` | 增加可选语义分类头，输出 `pred_logits` 仍保持原格式 |
| `src/rfdetr/config.py` | 增加 `semantic_head`, `text_prototype_path`, `text_logit_scale`, `text_loss_coef` 等配置 |
| `src/rfdetr/models/criterion.py` | 在匹配后的正样本上计算文本对齐和语义对比损失 |
| `tools/build_text_prototypes.py` | 离线生成类别文本原型，避免推理依赖 CLIP |

## 5. 改进二：基类到新类的原型迁移库

### 5.1 为什么原型库适配 RF-DETR

传统 FSOD 方法常在 Faster R-CNN 的 ROI 特征上构建原型。RF-DETR 没有 RPN 和 ROI head，但它有天然适合做原型的特征：每个正样本目标都会通过匈牙利匹配对应到一个 decoder query。这个 query 已经融合了局部视觉特征、全局上下文和目标位置信息，比纯 backbone patch 特征更接近检测语义。

因此，可以把匹配后的正样本 query 特征作为原型库输入。

### 5.2 原型库结构

建议维护两级原型。

1. **类别全局原型**：每个类别一个 EMA 向量 `P_c`，表示类别中心。

2. **尺度和外观子原型**：每个类别维护若干子原型 `P_{c,k}`，按目标面积、长宽比、场景上下文或在线聚类划分。遥感目标尺度变化大，单一原型容易把飞机、小船、大型舰船、密集车辆混在一起。

基类训练阶段，使用充足样本维护稳定原型。小样本新类阶段，用文本相似度初始化新类原型：

```text
P_novel_init = sum_c softmax(sim(text_novel, text_base_c) / tau) * P_base_c
```

然后用少量新类正样本 query 做 EMA 校准：

```text
P_novel = m * P_novel + (1 - m) * mean(query_features_novel)
```

建议 `m=0.9` 到 `0.99`，小样本越少，动量越大。

### 5.3 原型相关损失

原型库可以提供三类监督。

1. **原型分类辅助**：query 与所有类别原型计算余弦相似度，得到 `logit_proto`，与原分类 logits 融合。

2. **ProtoNegative 损失**：每个类别原型应远离其他类别原型，防止新类原型被相似基类吞掉。

3. **原型校准损失**：正样本 query 靠近所属类别原型，远离语义相似但标签不同的原型。

这部分比“单纯对比学习”更适合作为比赛故事，因为它明确回答了“新发射卫星初期只有少量在轨样本时如何从已有基类经验迁移到新类”。

## 6. 改进三：不均衡小样本训练策略

### 6.1 两阶段训练范式

推荐训练流程如下。

| 阶段 | 数据 | 训练参数 | 目标 |
| --- | --- | --- | --- |
| 基类预训练 | 历史遥感数据、公开遥感数据、比赛基类数据 | RF-DETR Small，正常训练或 LoRA | 建立遥感通用视觉特征和基类原型库 |
| 小样本平衡微调 | 每类 K-shot 样本，基类也按 K 重采样 | 冻结 backbone 或启用 LoRA，训练 head、decoder、prototype | 快速适配新卫星和新区域 |
| 全量校准 | 所有可用在轨标注，少数类过采样 | 低学习率，EMA，早停 | 控制虚警，稳定召回 |
| 推理阈值调优 | 验证集 | 按类别调 score 阈值和 NMS/WBF 阈值 | 满足召回和虚警硬指标 |

小样本微调时不要只训练新类样本，否则容易遗忘基类并让分类边界漂移。应构造“基类 K-shot + 新类 K-shot”的平衡集，保持类别间判别关系。

### 6.2 数据增强

遥感增强应优先服务小目标和域偏移。

| 增强类型 | 建议 |
| --- | --- |
| 几何增强 | 水平翻转、垂直翻转、任意角度旋转、轻量仿射缩放 |
| 辐射增强 | 亮度、对比度、Gamma、色彩扰动、轻微 CLAHE |
| 成像退化 | 轻微高斯模糊、运动模糊、压缩伪影、传感器噪声 |
| 小目标增强 | 少数类 Copy-Paste、目标保持裁剪、局部放大训练 |
| 类别均衡 | 含少数类图像过采样，batch 内类别尽量均衡 |

注意：车辆等小目标对模糊和缩放非常敏感，增强不能盲目加重。建议对小目标设置保护规则，裁剪后目标宽高低于 4 到 6 像素的样本不参与训练，或降低该增强概率。

### 6.3 参数高效微调建议

推荐从保守到激进进行三组实验。

1. **Head-only**：冻结 DINOv2 backbone，只训练分类头、bbox head、语义投影层、原型相关参数。适合极少样本，过拟合风险最低。

2. **LoRA 微调**：启用 `backbone_lora=True`，允许 backbone 以低秩方式适配新卫星成像风格。适合存在明显域偏移时。

3. **Decoder + Projector 微调**：解冻多尺度 projector 和 decoder，保持 backbone 大部分冻结。适合小目标召回不足时。

学习率建议：head 和 prototype 使用 `1e-4`，decoder 使用 `5e-5`，backbone 或 LoRA 使用 `1e-5` 到 `3e-5`。保留 EMA，使用早停和验证集阈值搜索。

## 7. 改进四：小目标与多尺度特征

当前 RFDETRSmall 默认 `projector_scale=["P4"]`，速度快但对极小目标不一定充分。遥感车辆和小船可能只有十几个像素，建议实验性打开 P3：

```text
projector_scale=["P3", "P4"]
```

若速度仍满足要求，再尝试 `["P3", "P4", "P5"]`。P3 提供更高分辨率定位信息，P5 提供大目标上下文。由于比赛最终推理在局部切片上进行，单切片模型稍慢可以通过减少切片数量、批量推理和 TensorRT 优化抵消。

训练切片尺寸建议按目标大小统计决定。若车辆原始框常在 8 到 20 像素，局部切片不能过大，否则 resize 到 512 后车辆会被压到不可检测。可准备两套 local detector：

| 模型 | 切片来源 | 目标 |
| --- | --- | --- |
| RF-DETR Small 512 | 768x768 或 1024x1024 切片缩放 | 通用检测，主推理模型 |
| RF-DETR Nano/Small 高召回版 | 512x512 小切片 | 车辆密集区、小目标补检 |

如果时间只允许实现一个模型，优先选择 RF-DETR Small 加 P3，并配合稀疏切片。

## 8. 改进五：10000x10000 大图稀疏推理

### 8.1 为什么不能简单密集滑窗

10000x10000 全图如果按 1024 切片、20% overlap 做密集滑窗，大约需要 144 到 169 个切片；若按 640 或 512 切片以保车辆小目标，切片数量会增加到数百个。Python 预处理、模型前向、后处理、坐标合并全部算上，很容易触碰 20 秒上限。更关键的是，大量遥感区域是背景，密集滑窗把算力浪费在空区域。

### 8.2 推荐稀疏推理流程

完整推理流程如下。

1. **低分辨率全局预览**：将 10000x10000 图像缩放到 1280 到 2048，运行轻量 Gain Map 网络或 RF-DETR Nano 的 objectness 分支，预测每个候选区域的目标覆盖得分。

2. **候选切片生成**：在原图坐标系中生成 512、768、1024 多尺度候选窗口。每个窗口得分由 Gain Map 积分、纹理显著性、道路/港区/机场先验和低分辨率检测结果共同决定。

3. **软抑制贪心选片**：每次选择当前最高得分窗口，选中后对重叠窗口做线性软扣分，而不是硬 NMS。这样既减少重复，又不容易漏掉密集目标区域。

4. **局部批量检测**：把选中的 K 个切片按 batch 送入 RF-DETR Small/Medium。推荐 batch size 8 到 16，FP16 或 BF16，导出 ONNX/TensorRT 后推理。

5. **坐标回映射和去重**：将局部框映射回全图坐标，按类别做 Weighted Boxes Fusion 或 Soft-NMS。车辆 IoU 匹配阈值为 0.35，去重阈值也应低于飞机和舰船，避免重复框提高虚警率。

6. **召回兜底**：保留少量均匀网格切片或低置信全局候选，专门覆盖 Gain Map 低响应但可能存在孤立车辆和小船的区域。

### 8.3 切片预算建议

建议按时间预算动态控制 K。

| 场景 | K 值建议 | 说明 |
| --- | --- | --- |
| 港口、机场、城市道路密集 | 80 到 120 | 召回优先，目标密集区收益高 |
| 普通郊区或背景稀疏 | 40 到 80 | 速度和召回平衡 |
| 几乎空旷区域 | 20 到 40 | 低虚警和速度优先 |

若局部 RF-DETR TensorRT 单切片平均 50 到 100 ms，K=80 时局部检测约 4 到 8 秒；加上全局预览、切片、后处理和 IO，仍有机会控制在 20 秒内。若 Python 端开销过高，应优先做批量预处理、GPU resize、固定尺寸 TensorRT engine 和异步数据搬运。

### 8.4 Gain Map 训练标签

Gain Map 不需要精细框回归，只预测每个候选窗口的目标覆盖收益。可从 COCO 标注自动生成标签：

```text
gain(window) = min(number_of_objects_inside_window, M)
```

也可以按小目标加权：

```text
gain(window) = sum_object w_object
w_object = 2.0 if object_area < small_threshold else 1.0
```

这样选片器会更偏向车辆和小船区域，减少小目标漏检。

## 9. 推理后处理与指标优化

比赛计算召回率和虚警率，不直接以 COCO mAP 排名。后处理策略应围绕这两个指标调优。

1. **按类别阈值搜索**：车辆目标 IoU 匹配阈值只有 0.35，召回更容易，但也容易重复框变 FP。车辆应使用较低 score 阈值加更严格去重；飞机和舰船使用较高 score 阈值控制虚警。

2. **重复检测控制**：多个切片重叠区域可能产生重复框。重复框除最高分外都会算 FP，必须在全图坐标做去重。

3. **空图虚警控制**：如果全局 Gain Map 判断整图低风险，可以提高局部检测阈值或减少兜底切片，避免空旷背景产生 FP。

4. **类别混淆合并**：初赛三大类合并计算整体指标，但分项排名仍重要。若训练为细粒度类别，提交前映射到三大类，同时保留细粒度分数用于阈值校准。

5. **置信度校准**：使用验证集做温度缩放或类别 bias 调整，让 score 更符合真实 TP 概率。小样本模型容易过度自信，校准能显著降低虚警。

## 11. 推荐落地优先级

### 第一优先级：必须做

1. RF-DETR Small baseline 训练和 TensorRT/ONNX 推理基准。
2. 遥感增强、类别均衡采样、少数类 Copy-Paste。
3. 10000x10000 稀疏切片推理流水线，包括坐标回映射和去重。
4. 按类别阈值搜索，直接优化召回率和虚警率。

### 第二优先级：最值得作为创新点

1. 离线 CLIP 文本原型加轻量语义分类头。
2. 基类原型库和新类原型初始化。
3. 语义加权监督对比损失。

### 第三优先级：有时间再做

1. P3/P4/P5 多尺度 projector 的速度和精度搜索。
2. Gain Map 网络端到端联合训练。
3. 多模型级联，例如车辆专用补检模型。

## 12. 风险与应对

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 文本语义不适配遥感视角 | 文本头提升不稳定 | 只作为辅助分支，保留原视觉分类头；使用遥感 prompt ensemble |
| 原型库被少量噪声样本污染 | 新类原型漂移 | EMA 高动量、只用高 IoU 正样本更新、维护多个子原型 |
| 对比损失压低召回 | 类间分离过强 | 降低 `beta`，只在正样本 query 上计算 |
| 稀疏选片漏掉孤立目标 | 召回不足 | 保留低成本均匀兜底切片，Gain Map 对小目标加权 |
| P3 多尺度拖慢速度 | 20 秒超时 | 仅局部模型启用 P3，减少 K 或切换 Small/Nano |
| 重叠切片重复框过多 | 虚警率上升 | 全图坐标 Soft-NMS/WBF，车辆设置独立去重阈值 |

## 13. 最终建议方案

最终推荐采用以下组合：

1. **模型基座**：RF-DETR Small，必要时局部检测阶段尝试 RF-DETR Medium；默认不使用 RF-DETR Base，不使用 NAS。
2. **训练策略**：历史遥感或基类数据预训练，比赛小样本做类别均衡微调；启用 EMA、LoRA 或冻结 backbone；强遥感增强但保护小目标。
3. **语义模块**：离线 CLIP 文本原型，语义余弦分类头，语义加权对比损失。
4. **原型模块**：从匹配 query 特征维护基类原型，新类原型由文本相似度加权继承，再用少量样本校准。
5. **推理系统**：低分辨率全局 Gain Map 加软抑制稀疏选片，高分辨率局部 RF-DETR 批量检测，全图坐标去重和阈值校准。

这条路线的优势是故事完整且工程可落地：RF-DETR 负责实时高精度检测，文本语义和原型迁移负责小样本不均衡，稀疏切片负责 10000x10000 大图速度，小目标由局部高分辨率与 P3 特征共同保障。相比单纯“加 CLIP”或“加对比学习”，该方案更能直接回应赛题中“新卫星、新区域、少量在轨样本、时敏目标、快速业务化”的核心需求。
