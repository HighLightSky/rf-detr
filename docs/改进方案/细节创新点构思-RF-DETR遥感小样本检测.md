# RF-DETR 遥感小样本检测细节创新点报告

## 1. 写作目的

前一版方案把 SCG-FSOD、UHR-DETR 和 RF-DETR 的思路组合成了一条可落地路线，但如果只是把"文本分支、原型库、对比学习、稀疏切片"搬过来，创新性会显得薄，而且这些论文模块本身也有一些细节假设并不稳。比赛最终不只看能不能堆模块，更看是否真的理解"不均衡小样本遥感目标检测"的关键矛盾。

本报告重点回答四个问题：

1. 参考论文中的哪些细节可能存在逻辑漏洞或工程浪费。
2. 这些漏洞放到 RF-DETR 上会被放大还是被缓解。
3. 我们可以提出哪些更细、更贴合比赛的创新点。
4. 哪些创新点值得优先实现，哪些适合作为报告中的技术储备。

结论先行：最值得做的创新不是"多加一个完整文本分支"，而是 **把文本语义蒸馏成 RF-DETR 的轻量分类权重和原型先验；把视觉原型从简单均值改为质量感知、多子原型、可靠性门控的 query 原型；把 UHR-DETR 的目标数量 Gain Map 改为面向召回和虚警的风险收益图；把 RF-DETR 的 query 和 decoder 计算预算变成由场景密度动态分配的推理资源。**

## 2. 对 SCG-FSOD 的细节反思

SCG-FSOD 的核心是 ISCT 原型迁移和 SSCL 语义加权对比学习。这个方向对比赛有启发，但不能照搬。

### 2.1 视觉原型"均值化"过于粗糙

SCG-FSOD 先用 memory bank 存 ROI 特征，然后对同类特征求均值得到原型。为了避免背景污染，它用置信度阈值 `t1` 过滤低质量特征，用相似度阈值 `t2` 过滤与当前原型过度相似的重复特征。这比普通 FIFO memory bank 好，但仍有几个问题。

1. **同类目标通常不是单峰分布**。遥感中的舰船有小艇、大型货船、停泊船、航行船；车辆有轿车、卡车、密集车流、阴影遮挡车辆；飞机有机身朝向、停机坪背景、尺度差异。一个均值原型会把多种形态压成一个中心，反而降低小样本新类的判别力。

2. **均值不区分定位质量**。同样是正样本特征，高 IoU 匹配框、低 IoU 匹配框、边缘截断目标、被遮挡目标对原型的贡献不应相同。只按分类置信度过滤，会保留一些"分类看起来像但定位不准"的特征。

3. **均值不区分样本难度**。小样本真正需要的是覆盖类内变化，而不是让常见外观占据原型中心。SCG-FSOD 用 `t2` 去掉过度相似样本是一个方向，但它只看与当前原型的相似度，没有显式保留尺度、方向、背景等多样性。

4. **原型更新早期不稳定**。论文的前 N 轮 FIFO 更新逻辑甚至在文本中重复写了两次，这本身不影响思想，但说明该设计偏经验化。对于 RF-DETR 这种 query 学习模型，早期 query 与目标的匹配会快速变化，过早积累原型可能把错误 query 固化进 memory。

### 2.2 新类原型校准的注意力加权加均值过于武断

SCG-FSOD 用新类初始原型作为 Q，基类原型作为 K/V，通过 cross-attention 得到基类加权组合 $p_w$，然后直接与新类初始原型做二分平均：

$$p_{\text{novel\_calibrated}} = (p_{\text{base\_weighted}} + p_{\text{novel\_initial}}) / 2$$

这个细节值得质疑。

1. **新类初始原型本身很噪**。K-shot 只有 3、5、10 个样本时，新类原型作为 Q 可能不可靠。用噪声 Q 去查询基类原型，注意力权重也会跟着噪。

2. **基类贡献和新类贡献固定 1:1 不合理**。3-shot 时更应依赖基类和文本先验，20-shot 时更应依赖新类视觉样本；类内变化大时应依赖多个子原型，而不是一个平均值。

3. **只用视觉原型做注意力可能学到伪相关**。例如"飞机"和"机场跑道"视觉上下文接近，但类别概念不同；"船"和"港口设施"背景接近但目标边界不同。没有文本或结构约束时，cross-attention 可能把背景相似性当成类别迁移依据。

4. **基类原型越多，注意力越稀释**。比赛若有较多历史类别或细粒度类别，所有基类全量参与 attention 会产生不必要噪声。新类只需要从少数可信邻居继承。

### 2.3 ProtoNegative 对所有类一刀切推远，可能伤害语义连续类

ProtoNegative 把所有不同类别原型都当负样本推开。这个设计能增强判别性，但对遥感检测不一定总是好。

1. 初赛目标会被合并为舰船、飞机、车辆三大类。如果内部训练采用细粒度类别，细粒度子类之间不应该被过度推远，否则提交前合并时分数校准会变差。

2. 相似类不一定都要远离。有些类共享视觉部件或上下文，例如不同车辆子类，共享原型有助于小样本泛化。过度排斥会损失可迁移性。

3. 只推原型距离，不考虑原型方差。如果某类本身类内方差很大，强行压到一个原型再推远，会造成类内塌缩。

### 2.4 SSCL 只用文本相似度加权负样本不够可靠

SCG-FSOD 用 CLIP 文本编码类别名，得到类别相似矩阵，再用它加权监督对比学习负样本。问题在于：

1. **类别名不等于遥感视觉相似性**。`vehicle` 和 `ship` 在语言空间都属于交通工具，但在遥感俯视图中视觉差异很大；`airplane` 和 `airport` 语言上相关，但一个是目标、一个是场景。

2. **固定 prompt 太弱**。论文示例使用单个类似 `a centered satellite photograph of {class}` 的 prompt。遥感目标的尺度、背景、视角、在轨成像条件都没有被表达。

3. **CLIP 文本空间和 RF-DETR 视觉空间未对齐**。直接用文本相似度指导 RF-DETR query 特征，默认两个空间中的相似关系一致，这个假设很强。DINOv2 的视觉特征和 CLIP 文本特征不是同一预训练目标。

4. **语义相似和混淆风险不是一回事**。真正应该被拉开的负样本，是验证集中经常互相误检的类别，或原型分布重叠的类别。文本相似只是先验，不能替代视觉混淆统计。

## 3. 对 UHR-DETR 的细节反思

UHR-DETR 对 10000×10000 大图很有启发，但它的 Gain Map 和 patch routing 也不能照搬。

### 3.1 Gain Map 优化的是覆盖数量，不是比赛指标

UHR-DETR 的 Gain Map 目标近似是窗口内目标覆盖数量，训练标签来自 IoF 累计并截断。这适合最大化目标覆盖，但比赛指标是召回率、虚警率和推理时间。

1. **数量多的多数类会主导选片**。如果车辆数量远多于飞机和舰船，Gain Map 会倾向车辆密集区，可能牺牲稀有但重要的飞机、舰船区域。

2. **容易目标和困难目标权重相同**。一个大飞机和一个极小车辆都算覆盖，但后者更容易漏检；一个清晰目标和一个阴影遮挡目标也不应等价。

3. **没有虚警成本**。某些背景纹理丰富区域会吸引 Gain Map，但检测后可能产生虚警。只看覆盖收益，不看虚警风险，会浪费 patch 预算。

4. **固定 K 不适应 20 秒约束**。比赛要求固定时间上限，不是固定 patch 数。应根据当前图像内容、模型耗时和硬件状态动态分配 K。

### 3.2 软抑制只考虑几何重叠，不考虑语义互补

UHR-DETR 的 ISSGA 用线性核扣除已选 patch 附近的 Gain，避免重复。这个设计简单有效，但仍然偏几何。

1. 两个重叠 patch 可能覆盖不同尺度目标或不同类别，简单扣分可能误伤边界密集区。

2. 两个不重叠 patch 可能是同一类容易样本，收益冗余；而一个低分 patch 可能覆盖稀有类或困难小目标，更值得选。

3. 对比赛而言，patch selection 的目标应该是"单位时间带来的召回提升减去虚警风险"，不是"覆盖最多物体"。

### 3.3 稀疏假设在均匀分布场景会退化

UHR-DETR 自己也承认，目标均匀散布时稀疏策略会退化到接近密集滑窗。比赛如果出现大面积道路车辆、码头密集船只、机场多区域停机坪，固定稀疏选片会面临两难：K 小则漏检，K 大则超时。

因此需要一个"密度模式识别 + 多分辨率兜底"的机制，而不是只依赖单一 Gain Map。

## 4. 对 RF-DETR 文本分支的反思

直接给 RF-DETR 加一个和视觉分类头平行的文本分支，表面上很自然，但很可能性价比低。

1. **如果视觉分支和文本分支都对每个 query 输出 C 类 logits，计算重复**。类别数不多时开销不算巨大，但在每张大图几十到上百个切片上累积，任何额外矩阵乘法和后处理都会放大。

2. **文本特征不能直接替代视觉判别**。CLIP 文本知道 `ship` 的语言概念，但不一定知道比赛中光学遥感小船在不同 GSD、阴影、港口背景下的视觉表现。

3. **DINOv2 与 CLIP 不天然对齐**。RF-DETR backbone 是 DINOv2，文本编码器通常是 CLIP。两者目标函数不同，直接余弦相似容易让文本分支成为弱噪声。

4. **开放词表能力不是比赛关键**。比赛类别范围明确，初赛还合并为三大类。我们需要的是小样本语义先验和稳定校准，不是完整开放词表检测。

所以文本分支应被设计成 **训练和初始化阶段的语义先验**，而不是推理阶段重复跑一套分类器。

## 5. 创新点一：质量感知多子原型 Query Memory

### 5.1 核心思想

把 SCG-FSOD 的 ROI 均值原型改成 RF-DETR 专用的 **质量感知多子原型 Query Memory**。原型不从 backbone patch 或 ROI 均值来，而从匈牙利匹配后的 decoder query 特征来，因为 query 已经融合了定位、上下文和目标语义。

> **⚠️ 批注：原型来源的根本性问题——循环依赖**
>
> 此处"原型从匈牙利匹配后的 decoder query 特征来"存在一个根本性的**循环依赖**问题：
>
> 1. **匈牙利匹配的前提是模型已经能较好检测目标**。但在小样本场景下，模型对新类的初始检测能力往往很弱——匹配本身不可靠，得到的 query 特征质量自然差。这形成了"富者愈富"的困境：模型已经能检测好的类获得优质原型，而真正需要原型帮助的困难类反而获得噪声原型。
>
> 2. **Decoder query 特征并非类别的"纯净"表示**。Decoder query 已经融合了 cross-attention 后的图像上下文信息（背景、邻近目标、光照等），原型中会混入训练图像特有的非语义信息，泛化性受限。相比之下，RoI Align 从 backbone 特征图提取的特征虽然也没有语义纯度保证，但至少不与 decoder 的匹配质量耦合。
>
> 3. **训练-推理不一致**。推理阶段没有 GT 和匈牙利匹配，原型更新机制只能在训练阶段运作，无法在推理时利用新观测持续自适应。
>
> **建议补充/修改方向**：(a) 原型构建可改为从 encoder 输出的 backbone 特征（在 GT 框位置做 RoI Align），解耦原型质量与检测质量；(b) 或采用两阶段策略——先用弱原型做初步检测，再用高置信度伪标签在推理时增量更新原型；(c) 至少在文中明确讨论这一循环依赖及缓解措施（如 warm-up 阶段使用 backbone 特征构建初始原型，待检测质量提升后再切换到 decoder query）。

对每个正样本 query $h_i$ 计算质量权重：

$$q_i = \text{IoU}_i^{\,a} \cdot \text{score}_i^{\,b} \cdot \text{stability}_i^{\,c} \cdot \text{size\_balance}_i^{\,d}$$

其中：

| 项 | 含义 |
| --- | --- |
| $\text{IoU}_i$ | 预测框与 GT 的 IoU，过滤定位不准的特征 |
| $\text{score}_i$ | GT 类别置信度，过滤分类不稳定特征 |
| $\text{stability}_i$ | 同一图像弱增强前后 query 特征或预测框的一致性 |
| $\text{size\_balance}_i$ | 小目标和稀有尺度加权，防止大目标主导原型 |

> **⚠️ 批注：stability 指标在小目标上的可靠性**
>
> `stability_i` 定义为"同一图像弱增强前后 query 特征或预测框的一致性"。对于遥感小目标（如 10×10 像素的小车），弱增强（如轻微颜色扰动或翻转）也可能导致 decoder query 特征发生显著变化（因为小目标的特征本身信噪比低），使得该指标在小目标上噪声较大。此外，"增强一致性高 → 原型质量好"这一因果关系需要更明确的论证——一致性高也可能意味着该 query 学到了对输入变化不敏感的平凡解（如总是预测背景区域的通用纹理），而非有判别力的目标表示。

然后为每类维护多个子原型，而不是一个均值：

$$P_c = \{p_c^{\text{small}}, p_c^{\text{medium}}, p_c^{\text{large}}, p_c^{\text{context}_1}, \ldots, p_c^{\text{context}_k}\}$$

子原型可按目标面积、长宽比、背景上下文或在线聚类更新。更新时采用质量加权 EMA：

$$p_k \leftarrow \text{normalize}(m_k \cdot p_k + (1 - m_k) \cdot q_i \cdot h_i)$$

> **⚠️ 批注：小样本下多子原型的碎片化风险**
>
> 在 K-shot（K=3, 5, 10）场景下维护多个子原型，每个子原型的支撑样本数会更少（可能仅 1-2 个），导致单个子原型极不稳定。子原型聚类（如按尺度、上下文）在极少量样本下容易产生随机划分——例如 3 个样本按尺度分成 small/medium/large 三个子原型，每个子原型只有一个样本，失去了"原型"应有的统计稳定性。建议增加一个**子原型合并/回退机制**：当某子原型的有效样本数（质量加权累计值）低于阈值时，自动回退到父类单原型或与最近邻子原型合并，避免碎片化。

### 5.2 相比 SCG-FSOD 的创新

| SCG-FSOD 做法 | 问题 | 我们的改法 |
| --- | --- | --- |
| ROI 特征均值原型 | 单峰假设强，忽略定位质量 | 匹配 query 的质量加权多子原型 |
| 置信度阈值过滤 | 只看分类，不看框质量 | IoU、score、增强稳定性联合权重 |
| 相似度阈值去重 | 保多样性不明确 | 显式尺度和外观子原型 |
| 所有样本等价 | 小目标容易被稀释 | 小目标和少数类带权更新 |

### 5.3 预期收益

该设计能更准确回答"少量在轨样本如何构建稳定类别表示"。尤其适合车辆和小船这类小目标，因为它们不会被飞机等大目标的稳定特征淹没。

## 6. 创新点二：可靠性门控的基类到新类原型迁移

### 6.1 核心思想

不要把基类加权原型和新类原型固定二分平均。改为 **可靠性门控迁移**：

$$p_n = r_v \cdot p_n^{\text{visual}} + r_b \cdot p_n^{\text{from\_base}} + r_t \cdot p_n^{\text{from\_text}}, \quad r_v + r_b + r_t = 1$$

三个可靠性权重动态计算：

| 权重 | 高的条件 |
| --- | --- |
| $r_v$ | 新类样本数较多、query 稳定性高、类内方差低 |
| $r_b$ | 存在与新类视觉和文本都相近的基类 |
| $r_t$ | 新类样本极少、视觉原型不稳定、类别名称语义明确 |

基类原型不是全量参与，而是 top-k 稀疏邻居参与：

$$N_k(n) = \text{topk\_base\_classes}(\text{sim\_text} + \text{sim\_visual} + \text{sim\_context})$$

$$p_n^{\text{from\_base}} = \sum_{b \in N_k(n)} \alpha_b \cdot p_b$$

其中 $\text{sim\_visual}$ 来自新类少样本 query 与基类子原型的相似度，$\text{sim\_text}$ 来自文本原型，$\text{sim\_context}$ 来自场景先验，例如飞机更常与机场上下文相关，船舶更常与水域和港口相关。

### 6.2 可靠性怎么估计

可用简单可落地的统计量：

$$r_v = \sigma\left(-\text{Var}(P_n^{\text{visual}}) + \log(\text{num\_samples}_n)\right)$$

$$r_b = \max_{b} \left(\text{sim\_text}(n, b) \cdot \text{sim\_visual}(n, b)\right)$$

$$r_t = \text{entropy\_margin}(\text{text\_prompt\_ensemble}_n)$$

解释：

1. 新类视觉样本多且类内方差低，则信自己。
2. 某些基类在文本和视觉上都相近，则信基类迁移。
3. 多 prompt 文本原型一致性高，则信文本先验。

> **⚠️ 批注：可靠性公式的多重问题**
>
> 1. **方差估计在极小样本下不可靠**：`Var(P_n_visual)` 在 K=3~10 时，方差本身的估计方差极大（例如从 5 个样本估计的方差，其置信区间宽度可达点估计的数倍），用它做门控决策会引入额外的不确定性。建议至少使用收缩估计（shrinkage estimator）或贝叶斯方法对方差进行正则化。
>
> 2. **量纲不匹配**：`Var` 的量级取决于特征空间的尺度（可能是 0.01~10），而 `log(num_samples)` 在 K=3~20 时取值约 1~3。两者直接相加后过 sigmoid 可能导致其中一个因素主导决策，应引入可学习的缩放参数，如 $\sigma(w_1 \cdot (-\text{Var}) + w_2 \cdot \log(N) + b)$。
>
> 3. **归一化矛盾**：公式声称 $r_v + r_b + r_t = 1$，但三个 r 分别由独立的 sigmoid/乘积/entropy_margin 函数给出，输出范围和尺度不一致，无法直接满足加和为 1 的约束。实际实现中需要用 softmax 做归一化，但这就改变了每个 r 的语义——它们只是 softmax 的 logits，而非独立的"可靠性"。建议明确：三个 r 是 softmax 归一化后的结果，上方的公式计算的是 softmax 前的 logits。
>
> 4. **$r_b$ 公式修正**：原稿中 $r_b = \max_b \text{sim\_text}(n,b) \times \max_b \text{sim\_visual}(n,b)$ 存在逻辑缺陷——文本上最相似的基类（如"卡车"）和视觉上最相似的基类（如"公交车"）可能是不同的类，乘积并不反映"存在同时满足文本和视觉相近的基类"。**已在正文公式中修正**为先对每个基类算乘积再取最大值：$r_b = \max_b (\text{sim\_text}(n,b) \cdot \text{sim\_visual}(n,b))$。

### 6.3 相比论文的创新

SCG-FSOD 是 `新类视觉原型 -> cross-attention -> 基类加权和 -> 与新类原型平均`。我们的设计多了三层约束：

1. **稀疏邻居**：只从 top-k 基类借知识，避免全量 attention 噪声。
2. **三源融合**：视觉、基类、文本都有可靠性估计。
3. **动态权重**：3-shot 和 20-shot 的迁移比例不同，不再固定 1:1。

## 7. 创新点三：文本不是并行分支，而是"语义权重生成器"

### 7.1 核心思想

不在推理时完整保留视觉分类头和文本分类头两套输出。文本只负责生成或校准分类权重。

具体做法：

1. 离线用 CLIP 文本编码器得到类别 prompt ensemble 原型 $t_c$。
2. 训练一个小投影器 $A_t$ 把文本原型映射到 RF-DETR hidden_dim。
3. 用映射后的文本原型初始化或正则化 `class_embed.weight`：

$$W_{\text{cls}}[c] = \text{normalize}(A_t(t_c)) + \Delta_c$$

其中 $\Delta_c$ 是小的可学习残差，用 LoRA 或低秩矩阵表示。

推理时：

$$\text{logit} = h_i \cdot W_{\text{cls}}[c] + \text{bias}_c$$

这和原 RF-DETR 线性分类头计算形式一致，不额外产生一套并行 logits。

### 7.2 为什么比双分支更好

| 双分支方案 | 语义权重生成方案 |
| --- | --- |
| 视觉 logits 和文本 logits 都要算 | 仍然只算一个分类头 |
| 两个分支可能冲突，需要调融合系数 | 文本变成分类权重先验，结构更简单 |
| 推理计算增加 | 推理几乎零额外开销 |
| 文本和视觉未对齐时变成噪声分支 | 通过残差 $\Delta_c$ 吸收域差异 |

### 7.3 文本对齐细节

文本原型不能只用一个类别名。建议使用多 prompt、多粒度和中文英文混合类别描述：

```text
a satellite photo of {class}
an overhead optical remote sensing image of {class}
a small {class} in complex background
a {class} viewed from space
类别中文名 + 典型场景描述
```

文本原型取 prompt ensemble 平均，同时计算 prompt 方差。方差高说明文本概念不稳定，应降低文本权重。

> **⚠️ 批注：prompt engineering 的局限性**
>
> 多 prompt ensemble 是合理的工程实践，但仅靠 prompt 设计无法解决 CLIP 文本空间与 DINOv2 视觉空间的根本性域差异。prompt 方差高可能意味着 CLIP 对该概念在不同语境下的表示不一致（如"ship"作为交通工具 vs. "ship"在遥感俯视图中的外观），也可能意味着概念本身在 CLIP 训练数据中覆盖不足。建议除了 prompt ensemble 的平均和方差外，额外引入一个**视觉-文本对齐度评分**（由第 7.4 节的 align_loss 在验证集上得出），作为文本原型可靠性的补充信号。

### 7.4 基类对齐训练

在基类阶段学习 $A_t$ 和视觉 adapter $A_v$：

$$\mathcal{L}_{\text{align}} = \text{CE}\left(\text{scale} \cdot \text{normalize}(A_v(h_i)) \cdot \text{normalize}(A_t(t_c)),\ y_i\right)$$

但最终不保留双分支，只把 $A_t(t_c)$ 融进分类权重。这解决"CLIP 文本空间和 DINOv2 query 空间不对齐"的问题。

## 8. 创新点四：视觉混淆驱动的语义对比学习

### 8.1 核心思想

不要只用 CLIP 文本相似度决定负样本权重。构造一个动态混淆矩阵：

$$H(c_1, c_2) = \lambda_t \cdot \text{TextSim}(c_1, c_2) + \lambda_v \cdot \text{VisualOverlap}(c_1, c_2) + \lambda_e \cdot \text{EvalConfusion}(c_1, c_2)$$

其中：

| 项 | 来源 |
| --- | --- |
| $\text{TextSim}$ | CLIP prompt ensemble 文本相似度 |
| $\text{VisualOverlap}$ | 类别原型分布重叠程度，如均值距离和协方差重叠 |
| $\text{EvalConfusion}$ | 验证集或训练中在线统计的误分类矩阵 |

对比损失中只加强真正混淆的负样本：

$$\mathcal{L} = -\log\frac{\text{pos}}{\text{pos} + \sum_j \exp\left(H(y_i, y_j) \cdot \text{sim}(i, j) / \tau\right)}$$

并设置上限，防止语义相似但视觉可分的类别被过度推开。

> **⚠️ 批注：VisualOverlap 在小样本下的协方差估计问题**
>
> `VisualOverlap` 基于"类别原型分布重叠程度，如均值距离和协方差重叠"。在小样本场景下，每个新类只有 3~10 个样本，协方差矩阵的估计几乎是奇异的（样本数 $N$ 远小于特征维度 $d$ 时协方差矩阵不可逆，$N < d$ 的情况在 256~1024 维特征空间中极易发生）。基于协方差的重叠度量（如 Bhattacharyya 距离、Wasserstein 距离、KL 散度）数值不稳定。建议在小样本阶段仅使用均值距离（如余弦距离或马氏距离配合对角协方差）作为视觉重叠的代理，待样本积累足够后再引入全协方差信息。
>
> **⚠️ 批注：三个 $\lambda$ 权重的尺度问题**
>
> `TextSim`（余弦相似度，范围 [0,1]）、`VisualOverlap`（可能是距离或重叠指数，范围不定）、`EvalConfusion`（混淆概率，范围 [0,1]）三者的数值尺度差异可能很大。如果 $\lambda_t, \lambda_v, \lambda_e$ 是手动设定的超参数，需要大量的调参工作；如果是可学习参数，则需要考虑各分量的归一化。建议对各项先做 min-max 或 z-score 归一化到统一尺度，再进行加权组合。

### 8.2 相比 SSCL 的创新

1. 文本相似只是先验，不是唯一依据。
2. 视觉原型重叠和真实误检更贴近比赛指标。
3. 可以按初赛三大类合并规则调整：同一大类内部子类不强推远，不同大类且易混淆才强推远。

这能避免"语言上相近但视觉上不混淆"的错误约束。

## 9. 创新点五：面向召回和虚警的 Risk-Gain Map

### 9.1 核心思想

把 UHR-DETR 的 Gain Map 从"窗口里有多少目标"改成"这个窗口值得花推理预算的期望收益"。收益定义为：

$$\text{RiskGain}(\text{window}) = \mathbb{E}[\text{recall\_gain}] - \mu \cdot \mathbb{E}[\text{false\_alarm\_cost}] + \rho \cdot \text{rare\_class\_bonus} + \sigma \cdot \text{small\_object\_bonus}$$

这比单纯目标计数更贴合比赛。

### 9.2 标签构建

从训练标注中自动构造窗口收益：

$$\mathbb{E}[\text{recall\_gain}] = \sum_i \text{IoF}(\text{window}, \text{box}_i) \cdot \text{miss\_risk}_i$$

$$\text{miss\_risk}_i = f(\text{object\_size}_i,\ \text{class\_frequency}_i,\ \text{detector\_confidence}_i)$$

其中小目标、少数类、当前模型低置信目标拥有更高 `miss_risk`。

> **⚠️ 批注：miss_risk 中的循环依赖**
>
> `miss_risk` 使用了当前检测器的置信度作为输入，但 Risk-Gain Map 的目的是指导切片选择以**提升**检测召回——它的构建又依赖于当前检测器的输出，形成循环：
>
> - 若检测器在某区域置信度低是因为训练不充分或域差异 → miss_risk 给高分 → 引导更多切片去该区域 → **合理**。
> - 若检测器在某区域置信度低是因为那里确实没有目标（复杂背景纹理） → miss_risk 仍给高分 → 切片资源浪费在背景区域 → **不合理**。
>
> 建议区分两种不确定性：(a) **认知不确定性**（epistemic——模型没见过类似样本），用验证集上的误检/漏检统计来刻画；(b) **偶然不确定性**（aleatoric——数据本身模糊），用同一区域多次推理的置信度方差来刻画。对前者应分配更多切片预算（探索），对后者应保守。

虚警成本可以从 hard negative mining 得到：

$$\text{false\_alarm\_cost}(\text{window}) = \text{fp\_score\_sum}(\text{window}; \text{model}_{\text{prev}})$$

也就是说，Risk-Gain Map 不只学习"哪里有目标"，还学习"哪里容易漏"和"哪里容易误报"。

> **⚠️ 批注：hard negative mining 的冷启动问题**
>
> 虚警成本来自"前一版模型"，这意味着需要先有一个可工作的检测器才能构建 Risk-Gain Map。在项目初期没有成熟模型时，虚警成本项无法获得有意义的估计。建议：(a) 第一轮训练时仅使用 recall_gain 项（$\mu=0$），待模型收敛后再引入虚警成本；(b) 或使用一个轻量的非深度方法（如基于纹理复杂度的 CFAR 类方法）提供虚警成本的初始估计。

### 9.3 动态时间预算

切片选择不固定 K，而是解一个近似背包问题：

$$\begin{aligned}
\text{maximize} \quad & \sum \text{RiskGain}(\text{patch}) \\
\text{subject to} \quad & \sum \text{latency}(\text{patch\_size}, \text{model\_variant}) \leq 20\text{s} - \text{overhead}
\end{aligned}$$

patch 有不同尺寸和模型选项：

| patch 类型 | 用途 |
| --- | --- |
| 512×512 + Nano/Small | 车辆、小船等小目标密集区 |
| 768×768 + Small | 通用区域 |
| 1024×1024 + Small/Medium | 飞机、舰船等大目标和上下文区域 |

这样可以把 UHR-DETR 的固定 patch size 和固定 K 改成比赛约束下的动态资源分配。

## 10. 创新点六：语义多样性的软抑制选片

UHR-DETR 的 ISSGA 只按几何重叠扣分。我们可以引入语义多样性：

$$\text{score}(\text{patch}) = \text{RiskGain}(\text{patch}) - \text{overlap\_penalty}(\text{selected}, \text{patch}) - \text{redundancy\_penalty}(\text{selected\_semantic}, \text{patch\_semantic})$$

`patch_semantic` 可以来自低分辨率全局模型的类别概率、场景上下文或原型相似度。这样：

1. 已经选了很多车辆密集区后，系统会更愿意补一个可能含飞机或舰船的中等收益区域。
2. 两个几何重叠 patch 如果分别覆盖不同尺度目标，扣分可以降低。
3. 对同质背景反复选片会被抑制，减少虚警。

> **⚠️ 批注：全局模型不可靠时的退化问题**
>
> `patch_semantic` 来自"低分辨率全局模型的类别概率、场景上下文或原型相似度"。这隐含假设低分辨率全局模型已经能给出有意义的语义信号。但在极端小样本场景下，全局模型本身对新类的预测可能近乎随机，语义多样性指导可能失效或误导（例如全局模型将港口误判为机场，导致系统错误地抑制了对港口区域的选片）。建议补充一个**置信度门控回退策略**：当全局模型的预测熵高于阈值时，退化为纯几何的 ISSGA 选片（即 `redundancy_penalty = 0`），避免不可靠的语义信号造成负优化。

这是对 ISSGA 的直接改进，容易写成创新点，也比较容易实现为后处理算法。

## 11. 创新点七：RF-DETR Query 预算动态化

RF-DETR 论文指出 query 数和 decoder 层数是重要速度杠杆，且推理可丢弃低置信 query。开源代码中 `LWDETR.forward()` 推理时使用 `self.refpoint_embed.weight[: self.num_queries]` 和 `self.query_feat.weight[: self.num_queries]`，这说明 query 数本身可以作为推理预算控制点。

### 11.1 场景驱动 query 数

根据 Risk-Gain Map 和局部 patch 密度，为每个切片分配不同 query 数：

| patch 类型 | query 数 |
| --- | --- |
| 空旷或低风险 patch | 50 到 100 |
| 普通 patch | 150 到 200 |
| 密集车辆或港口 patch | 300 |

如果 RF-DETR 的权重加载和导出流程支持固定 `num_queries` 的多个 engine，可以预导出 100/200/300 query 三个 TensorRT engine。若不方便多 engine，则在 PyTorch/ONNX 前处理阶段保留 query mask 或选择不同模型变体。

> **⚠️ 批注：多 engine 方案的工程可行性**
>
> 预导出多个 TensorRT engine 的方案在实际中面临几个工程挑战：
>
> 1. **显存开销**：三个 engine 同时驻留显存是单 engine 的三倍（虽然权重可尝试共享，但 TensorRT 的 engine 是自包含的序列化文件，跨 engine 权重共享并非原生支持）。
> 2. **Query 数是结构参数**：RF-DETR 的 `num_queries` 在 `__init__` 中确定，决定了 `query_feat` 和 `refpoint_embed` 的 `nn.Embedding` 维度。修改 query 数需要重新构建模型并导出，无法在已导出的 engine 上动态切换。
> 3. **切换开销**：在 20 秒时间约束下，频繁在不同 engine 之间切换（加载/卸载）的时间成本可能抵消动态 query 数带来的收益。
>
> 更实际的替代方案：(a) 导出最大 query 数（如 300）的单个 engine，推理时通过置信度 mask 丢弃低分 query，虽不能节省 encoder 计算但可加速 decoder；(b) 或只使用两个模型变体（Nano 用于简单区域，Small 用于复杂区域），而非三个 query 数的 engine。

### 11.2 原型 query 初始化

可以把部分 query 设计成类别或尺度原型 query：

$$\text{query\_feat} = \text{learned\_query} + \text{class\_proto\_bias} + \text{scale\_proto\_bias}$$

例如车辆密集 patch 注入更多小目标 query，机场 patch 注入飞机 query，港口 patch 注入船舶 query。这样 query 预算不仅减少数量，还更有方向。

> **⚠️ 批注：原型 query 初始化的定位-分类耦合**
>
> RF-DETR 的 query 同时负责定位和分类，将类别原型偏置注入 query 可能使 query 偏向特定类别，影响其对其他类别目标的定位能力。例如在一个同时包含车辆和飞机的混合区域 patch 中，注入"车辆"偏置的 query 可能对飞机产生定位偏差。建议：(a) 原型偏置仅作用于分类 embedding 部分，不改变 query 的定位相关维度；(b) 或保留一部分无偏置的通用 query 用于补充检测未被原型覆盖的类别。

### 11.3 Decoder 早退

RF-DETR 对各 decoder 层都有辅助监督，理论上可做 decoder 层数裁剪。我们可以根据 patch 风险选择 decoder 层数：

| patch 风险 | decoder 层 |
| --- | --- |
| 低风险兜底 | 1 到 2 层 |
| 普通 | 3 层 |
| 小目标密集或高混淆 | 3 到 4 层 |

这比单纯全图同一模型更符合 20 秒硬约束。

## 12. 创新点八：小样本训练中的"支持集一致性"

在小样本场景，过拟合往往来自模型记住了少数样本的纹理。可以给原型和分类头加支持集一致性约束。

对同一个标注目标做两种增强视图，经过 RF-DETR 后得到两个匹配 query：

$$h_i^{\text{weak}},\ \text{box}_i^{\text{weak}}$$
$$h_i^{\text{strong}},\ \text{box}_i^{\text{strong}}$$

约束：

$$\mathcal{L}_{\text{consistency}} = 1 - \cos(h_i^{\text{weak}}, h_i^{\text{strong}}) + \mathcal{L}_{\text{box\_consistency}} + \mathcal{L}_{\text{score\_consistency}}$$

只有 GT 可匹配且增强后目标仍有效时计算。该损失能让原型学习"目标本身"，而不是某个具体样本的背景或光照。

> **⚠️ 批注：增强一致性的双重使用**
>
> 第 5.1 节的 `stability_i`（质量权重中的增强一致性）与此处的 $\mathcal{L}_{\text{consistency}}$（训练损失中的增强一致性）都在利用增强前后的一致性信号，但目的不同——前者用于加权原型更新的贡献度，后者作为显式优化目标。在最终系统中两者同时存在可能导致对同一信号的**重复利用（double counting）**：模型既被 loss 约束要保持增强一致性，原型更新时又被同一一致性信号加权。建议明确两者的关系：(a) 是互补的（`stability_i` 筛选可靠样本，$\mathcal{L}_{\text{consistency}}$ 进一步优化被选中的样本）；(b) 还是可替代的（选其一即可）；(c) 若是递进关系，建议先只用 $\mathcal{L}_{\text{consistency}}$ 作为 loss 训练，再从中计算 stability 作为后验质量指标，而非在训练中同时使用。

这对新卫星、新区域尤其重要，因为成像风格会变，目标语义不变。

## 13. 建议形成的最终创新贡献

建议最终研究报告中把创新点组织成三个主要贡献，而不是列八个散点。

### 贡献一：QCPM，质量校准的跨模态原型记忆

全称可写为 **Quality-Calibrated Prototype Memory**。

内容包括：

1. 用 RF-DETR 匹配 query 构建视觉原型，而不是 Faster R-CNN ROI 均值。
2. 用 IoU、score、增强一致性和小目标权重进行质量感知更新。
3. 每类维护尺度和上下文多子原型。
4. 新类原型由视觉少样本、基类邻居和文本先验通过可靠性门控融合。

这是对 SCG-FSOD 原型模块的主要创新。

### 贡献二：T2W，文本到权重的轻量语义适配

全称可写为 **Text-to-Weight Semantic Adapter**。

内容包括：

1. CLIP 文本编码器只离线使用，推理不运行文本模型。
2. 文本 prompt ensemble 生成类别语义锚点。
3. 通过基类训练对齐 DINOv2 query 空间和文本空间。
4. 文本原型用于初始化或正则化 RF-DETR 分类权重，而不是额外并行分类分支。

这是对"文本分支计算翻倍但收益有限"的回应。

### 贡献三：RGR，风险收益驱动的大图稀疏推理

全称可写为 **Risk-Gain Routing**。

内容包括：

1. Gain Map 从目标数量预测改为召回收益、虚警成本、少数类和小目标加权收益。
2. patch 选择从固定 K 改为 20 秒时间约束下的动态预算分配。
3. 软抑制加入语义多样性，减少同质 patch 冗余。
4. RF-DETR query 数、decoder 层数和 patch 尺寸根据区域风险动态调整。

这是对 UHR-DETR 稀疏推理模块的主要创新。

## 14. 实现优先级

| 优先级 | 创新点 | 实现难度 | 建议 |
| --- | --- | --- | --- |
| P0 | 文本到分类权重初始化 | 中 | 最先做，成本低，故事清楚 |
| P0 | 质量加权 query 原型 | 中 | 与 RF-DETR 最贴合，建议实现 |
| P0 | Risk-Gain Map 初版 | 中 | 直接服务 20 秒大图指标 |
| P1 | 可靠性门控新类原型 | 中高 | 有创新性，适合做消融 |
| P1 | 视觉混淆驱动对比损失 | 中 | 比纯文本 SSCL 更合理 |
| P1 | 语义多样性选片 | 中 | 可先作为后处理实现 |
| P2 | 动态 query 多 engine | 高 | 工程收益大，但实现复杂 |
| P2 | decoder 早退 | 高 | 依赖导出和性能验证 |

如果时间紧，建议至少完成前三个 P0：**T2W 文本到权重、质量加权 query 原型、Risk-Gain Map 初版**。这三点已经足以形成区别于参考论文的技术主线。

## 15. 可以写进答辩的关键表述

1. 我们没有把 CLIP 当成在线检测分支，而是把语言先验蒸馏进 RF-DETR 的分类权重，因此保留 RF-DETR 的实时性。

2. 我们没有简单平均少量新类样本构建原型，而是使用 RF-DETR 匹配 query，并按定位质量、分类置信度、增强一致性和目标尺度进行质量校准。

3. 我们没有把所有基类原型平均迁移给新类，而是根据视觉相似、文本相似和样本可靠性进行稀疏邻居迁移。

4. 我们没有用目标数量作为大图切片唯一标准，而是以召回收益、虚警风险、小目标权重和时间预算为目标进行动态路由。

5. 我们的创新点不是绕开 RF-DETR，而是把 RF-DETR 的 query、decoder、分类头和实时推理特性利用起来，形成适合小样本遥感时敏目标检测的专用改造。

## 16. 与参考论文的关系

| 参考论文 | 可借鉴点 | 不照搬的原因 | 我们的创新 |
| --- | --- | --- | --- |
| SCG-FSOD | 语义相关、原型迁移、对比学习 | ROI 均值原型粗糙，文本相似不等于视觉混淆，新类和基类固定平均不合理 | 质量加权 query 多子原型，可靠性门控迁移，视觉混淆驱动对比 |
| UHR-DETR | Gain Map、稀疏 patch、全局到局部 | Gain 只看覆盖数量，固定 K 和 patch size，不直接服务召回/虚警/20 秒指标 | Risk-Gain Map，时间约束动态路由，语义多样性软抑制 |
| RF-DETR | DINOv2、实时 DETR、query 和 decoder 速度杠杆 | NAS 不可用，直接双文本分支浪费 | 文本到分类权重，动态 query 预算，原型 query 初始化 |

最终可以把项目命名为 **QTR-RF-DETR**：Quality-calibrated Text-prototype and Risk-routing RF-DETR。这个名字对应三条创新线：质量校准原型、文本到权重适配、风险收益大图路由。比单纯"CLIP + prototype + contrastive"更像一个围绕赛题细节设计的完整方法。
