# 大图切分策略梳理与虚警分析

- 文档日期：2026-08-14
- 相关分支：`large-cut`
- 实验目录：`output/0813-强基线-多原型/`
- 相关代码：`src/scripts/tiling.py`、`src/scripts/eval_lib.py`、`src/visualization/detection.py`
- 评测配置：`configs/experiments/test_shwx_large.yaml`

本文档梳理"大图滑窗切分推理"三轮策略（朴素滑窗+NMS → 中心归属合并 → 触边残框重裁）的
实现与效果，并重点分析为什么引入大图评测后虚警率（FDR）一直明显高于"没有大图之前"
的小图评测水平，以及其中的结构性原因。

---

## 1. 背景与评测口径

### 1.1 比赛刚性门槛

比赛（见 `docs/比赛方案/评分方案.md`）初赛对性能有**刚性指标门槛**：

- 时敏目标整体检测召回率 ≥ 85%
- **虚警率 ≤ 20%**（FDR = FP / (FP + TP)，三类合并计算）
- 单幅 10,000×10,000 像素图像推理时间 ≤ 20 秒

其中虚警率门槛是本次分析的核心关注点：比赛测试图最大达 12000px 量级，而模型输入为
1024 分辨率，**大图必须切分推理**；切分引入的虚警问题直接决定能否过门槛。

### 1.2 大图评测集

| 项目 | 说明 |
|---|---|
| 数据集 | `SHWX-dataset-dict-redo-large`（当前版） |
| 组成 | 672 张小图（700–900px）+ **100 张 hstrip 拼接大图**（2000–12000px），共 772 张 |
| GT | 共 26389 框：小图 3473 + 大图 22916（平均每张大图约 229 框） |
| 大图生成 | `make_hstrip_test.py`：小图按 0.8–1.4x 缩放、边贴边无缝拼接（不旋转不裁切），行尾/底部黑底填充，GT 坐标精确换算（理论零精度损失） |
| 评测口径 | conf=0.25，IoU ship/aircraft=0.50、vehicle=0.35；小图整图直连，大图滑窗切分（tile=1024，overlap=256） |

## 2. 三轮切分策略与效果

### 里程碑 1（8月13，commit `3f58b484`）：朴素滑窗 + 按类别 NMS

**实现：**

- `tile_origins` 生成滑窗原点网格（overlap=256，末块夹取贴边，无缝隙）；
- `_TileDataset` + DataLoader worker 预取流水线：worker 并行解码大图并切块（每 worker 缓存
  当前一张大图，~400MB），主线程把来自不同大图的 tile 混合成 GPU 批量持续前向，避免串行
  解码大图时 GPU 空转；
- 全部预测框映射回全图坐标后逐张做**按类别 NMS**（IoU=0.5，类间不互相抑制）。

**结果（hstrip 772 张）：** 预测 32907 框，TP=25364，FP=7543，FDR=**0.2292** ——
**超出比赛 20% 门槛**。

**已记录的两个已知缺陷：**

1. 跨块目标被切开 → 双侧残框（NMS 对 IoU<0.5 的残框对无能为力）；
2. NMS 可能把重叠区内两个真实相邻目标误合并（误删真目标）。

### 里程碑 2（8月14 10:14，commit `76d64ffa`）：center 中心归属 + 极严格安全合并

**实现：**

- **core/halo 中心归属**：每块只保留"预测框中心落在该块核心区内"的框。核心区按 halo
  （=overlap/2）剥离重叠带，恰好铺满全图无缝隙 → 每个目标的中心至多落在一个核心区内，
  **跨 tile 重复预测在源头结构性消除**；
- **`merge_center_duplicates` 兜底**：只抑制同时满足以下条件的框对——来自不同 tile、同类别、
  IoU>0.9、中心距离<0.1×min(两框对角线)、面积比∈(0.5,2)。同 tile 内框对**永不合并**
  （相邻真实目标完全免疫，这是与 NMS 的本质安全差异）。

**结果（hstrip 772 张）：** 预测 29562 框，TP=25317，FP=4245，FDR=**0.1436** ——
相对里程碑 1 **FP -44%**，回到 20% 门槛内；TP 略降（25364→25317），残框救不回来。

**验证：** `eval-large-center`（10:04）与 `eval-large`（10:18）逐位一致；`eval-large-center-verify`
（11:19，重构后代码）与之一致；另外 8月13 晚 `eval-old-code` vs `eval-refactor-verify`（672 张
小图、旧标注 3391 GT）也是字节级一致 —— 重构代码无行为变化。

### 里程碑 3（8月14，未提交）：center_rescue 触边残框定向重裁

**实现：** center 基础上，收集"触边残框"（预测框触到 tile 内容边界、且该边不是图像边界），
以残框**内侧边**为基准向缺口方向重裁 R 宽（留 margin=24）后重检，三闸门接受候选：
完整包含残框（容差 2px）+ 向每个缺口方向延伸 ≥4px + 同类别；重检失败保留残框兜底。

**结果（hstrip 772 张）：** 预测 29534 框，TP=25320（+3），FP=4214（-31），FDR=**0.1427** ——
相对 center 仅微小改善，救回了极少量被切大目标。

### 对照实验

| 实验 | 内容 | 结果 |
|---|---|---|
| A. `0813-最强-测试随机大图eval-large`（8月13 22:10） | **concat（mosaic）大图集** 772 张/37304 GT，里程碑 1 策略 | FP=9728，FDR=**0.2132**，同样超门槛 |
| B. 小图整图评测（同 checkpoint，672 张） | 无大图切分 | FP=341，FDR=**0.0931** |

## 4. 为什么"大图虚警一直很高"

### 4.0 直观数字

- 引入大图后整体 FP 从 **341 → 4245（约 12.5 倍）**，其中约 **3900 个 FP（92%）来自仅占
  图像数 13% 的 100 张大图**；
- 100 张大图共切出 **8080 个块**（平均 80.8 块/张），总模型视图从 672 涨到 8758（**12 倍**）。

### 4.1 机制一：视图基数效应（主因，结构性）

把 FP 按"每次模型前向"归一化：

| 路径 | 视图数 | FP | FP/视图 |
|---|---|---|---|
| 小图整图 | 672 | 341 | **0.51** |
| 大图切块（center） | 8080 | ≈3900 | **0.48** |
| 大图切块（nms） | 8080 | ≈7200 | **0.89** |

- **center 策略下，大图每块（1024×1024）的 FP 率与小图每张（也是 1024 前向）几乎相同**
  （0.48 vs 0.51）——模型本身的每视图误检率没有变坏；
- 切分把"一张大图一次前向"拆成了 **80.8 次独立前向**，每次前向约 0.5 个 FP 的固有率不变，
  **FP 绝对数随视图数线性放大 12 倍**；
- 这是**结构性上限**：只要滑窗切分，虚警基数 ≈ 每视图固有 FP 率 × 视图数。要降虚警，
  只能降每视图 FP 率（模型/阈值/重检）或减少冗余视图，合并策略只能压"重复类"虚警，
  压不掉"固有类"虚警。

### 4.2 机制二：GT 密度稀释，FDR 分子分母不对称

- 大图每视图 GT 数：22916 / 8080 ≈ **2.84**；小图每视图：3473 / 672 ≈ **5.17**；
- hstrip 大图含大量黑底填充、行间空隙与稀疏区域，且目标 0.8–1.4x 缩放后密度降低 →
  切出的块相对"空"；
- 相同 FP 率下，FDR = FP/(FP+TP) 的分母随 GT 密度下降，**每 GT 口径的 FDR 翻倍**
  （小图 0.093 → 大图 ~0.15）；
- 比赛按 FDR 计门槛 → 大图评测对虚警天然更敏感，这是"看起来虚警一直很高"的直接观感来源。

### 4.3 机制三：切块残框与跨块重复（合并策略可压的 44%）

- nms 每视图 FP 0.89 vs center 0.48，差出的约 3300 个 FP（全部 FP 的 43%）是**残框对与
  跨块重复预测**：
  - 目标横跨块边界被切开，两个残框各盖目标一部分，两框之间 IoU 通常 0.3–0.7（互不重叠
    或小重叠）→ NMS（0.5）压不掉、center 严格合并（需 IoU>0.9）也压不掉；
  - 残框与 GT 的 IoU 不足（只盖住部分目标）→ 匹配不上 → 被记为 FP；
  - 中心归属把"同一目标在两个块里各预测一次"这类重复在源头消除，所以 center 能压掉 44%；
- **center 把大图每视图 FP 率压到了与小图持平（0.48 ≈ 0.51）**，说明合并策略对大图虚警是
  决定性的（里程碑 2 相对里程碑 1 的核心收益）；剩余 FP 中能再压的空间只剩"IoU 0.5–0.9 的
  残框对"与模型固有误检。

### 4.4 机制四：小目标类误检集中（模型固有）

- MS 一个类贡献 2566 个 FP（60%），QHS/FSC/HM/LQS 合计再贡献 700+；飞机类 20 个类合计仅
  940（FDR 0.043）；
- MS 等为几像素级小目标，拼接 0.8–1.4x 缩放后更小，海面波浪、陆地纹理、港口设施等背景
  极易与之混淆；
- 切分把 12 倍视图全量喂给模型 → 小目标类的误检次数被同倍放大，绝对 FP 数随之放大；
- 这与小图评测一致（小图 FP 也主要落在 ship 大类，强SSCL 小图 ship FP=246/341≈72%）——
  **模型对 MS 的每视图误检率本来就高，大图评测只是把它显性化了**。

### 4.5 机制五：GT 口径漂移（评测层面）

- 同一 checkpoint、同 772 张图像，concat 版（37304 GT）测出 FDR=0.2132，hstrip 版
  （26389 GT）测出 0.1436——**"虚警数字"随 GT 版本大幅漂移**，两版评测结果不可直接对比；
- 8月13 23:50 hstrip 版替换 concat 版，两轮大图评测（22:10 与 8月14 上午）口径不连续；
- 拼接 GT 虽由脚本精确换算（理论零精度损失），但大图目标密集、遮挡区域复杂，**漏标对象
  被模型检出时会计为 FP（伪虚警）**，使"虚警一直很高"里混入一部分标注误差。

### 4.6 次要因素：两条路径的目标尺度分布不一致

- 小图路径：700–900px 图像上采样到 1024 推理（约 1.1–1.5x）；
- 大图切块路径：hstrip 先 0.8–1.4x 缩放，切块后以原生 1024 推理（无上采样）→ 目标有效
  尺度系统性偏小，小目标更接近模型尺度过小的一端；
- 训练配置 `scale_jitter=True`（1024 训练）能部分覆盖该偏移，但拼接图"接缝纹理、黑底、
  极高密度"的内容组合仍在训练分布之外。

### 4.7 结论

**"大图虚警一直很高"是以下因素叠加：**

1. **视图基数放大 12 倍**（结构性主因）：100 张大图 → 8080 块，每块 ~0.5 FP 的固有率
   不变，FP 绝对数线性放大；
2. **GT 密度稀释**：大图每视图 GT 只有小图的 ~55%，FDR 分子分母不对称，数字上虚警
   "变高"约一倍；
3. **切块残框/跨块重复**：贡献全部 FP 的 ~43%，已通过 center 合并压掉；剩余 IoU 0.5–0.9
   的残框对是下一步合并优化的对象；
4. **小目标类误检集中**：MS 单类占 60% FP，模型固有误检率被 12 倍视图放大；
5. **GT 口径漂移**：concat/hstrip 两版大图集不可比，部分"虚警"是标注版本噪声。

**现状**：FDR 已从 nms 的 0.2292（超 20% 门槛）压到 center_rescue 的 0.1427（门槛内），
但相对小图口径（0.093）仍高约 50%，且高度依赖合并策略，不稳健。

## 5. 下一步建议

1. **合并侧（立竿见影）**：针对"IoU 0.5–0.9 的跨 tile 残框对"（中心距近、面积比偏离、
   触边特征）设计定向合并/统一重检规则——center_rescue 只重裁了"真残框"，可推广为对
   "被切目标"集合的整体重检；
2. **阈值侧**：对 MS/QHS/FSC 等小目标类用 `class_conf_thresholds` 按类提置信度阈值
   （需评估 recall 代价，MS recall 目前 0.831）；或对"中心靠近块边缘"的预测做置信度衰减
   （边缘预测可靠性低）；
3. **评测基准化**：固定 hstrip 版大图集为唯一大图口径；补测 concat 集与真实 10000×10000
   原图；统一 GT 计数逻辑（3429/3473/3661 的口径噪声应消掉）；
4. **训练侧**：训练增广中引入"切块边界"模拟（随机裁窗使目标贴边），提高模型对残框的
   判别力；SSCL 多原型/难负样本等训练侧消融需在大图口径复测（小图口径 FDR 0.096–0.105
   不可分，结论在大图上可能翻转）；
5. **部署侧**：比赛单幅 10000×10000 ≤ 20s 门槛——当前混合负载稳态吞吐约 42 img/s，
   单张 10000×10000 约 161 块，需实测单图端到端耗时确认达标。
