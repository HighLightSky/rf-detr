# 构建提交镜像说明

## 模型如何路由

镜像内置配置固定在 `/app/competition/configs/submission.yaml`。配置中的
`detector.roles.*.model` 和 `proto_guidance_artifact` 只能填写文件名，程序会把它们解析到
`/app/models`，不会从宿主机挂载目录、网络或 PyTorch 缓存寻找模型。

例如当前第二个版本的路由为：

| 角色 | 配置文件名 | 容器内路径 |
| --- | --- | --- |
| `main` | `shwx_proto_hardneg_26cls_truck_1024.pth` | `/app/models/shwx_proto_hardneg_26cls_truck_1024.pth` |
| `main` 原型 | `proto_guidance_shwx_truck_26.pt` | `/app/models/proto_guidance_shwx_truck_26.pt` |
| `boundary` | `boundary.pth` | `/app/models/boundary.pth` |

`output/最终提交五个版本/` 下每个版本目录都包含自己的 `submission.yaml` 和权重。切换版本时，
必须让 YAML 中的文件名与 `deploy/models/` 中的文件名一一对应；不要只替换权重而保留另一版本的
原型文件或配置。

当前第二个主模型虽然包含第 26 类辅助 `truck`，比赛类别名称资源仍只有 25 类。后处理会丢弃
所有类别编号大于等于 25 的预测，因此该辅助类仅参与模型推理，不会写入提交 JSON。

## 权限修复

此前主模型为 `0600`，Docker 的 `COPY models /app/models` 会保留该权限。平台以非 root 用户运行
`python /app/main.py` 时，`torch.load()` 因无法打开 `/app/models/main.pth` 而失败。模型不需要
`sudo`；`sudo docker ...` 只是在宿主机访问 Docker daemon 的权限要求。

现在 Dockerfile 在复制模型后执行 `chmod -R a+rX /app/models`，因此无论构建上下文中的模型原始
权限如何，镜像内所有用户都能读取模型和原型工件。`prepare_delivery_assets.py` 复制资产时也会补齐
读取权限。

## 构建步骤

以某个版本目录为例，先清空旧的交付模型，再复制该版本的三个文件和配置：

```bash
rm -f deploy/models/*
cp "output/最终提交五个版本/2-26类-多模态原型-裁切800以下-ms-fsc-NMS/"*.pth deploy/models/
cp "output/最终提交五个版本/2-26类-多模态原型-裁切800以下-ms-fsc-NMS/"*.pt deploy/models/
cp "output/最终提交五个版本/2-26类-多模态原型-裁切800以下-ms-fsc-NMS/submission.yaml" \
   deploy/app/competition/configs/submission.yaml
chmod a+r deploy/models/*
cd deploy
sudo docker build --pull=false -t detector-pytorch:variant-2 .
```

`--pull=false` 只是不主动更新基础镜像；它不会影响 Dockerfile 中的权限修复。构建完成后，在提交
前用非 root 用户检查镜像内文件权限和配置路由：

```bash
sudo docker run --rm --entrypoint sh detector-pytorch:variant-2 -c \
  'stat -c "%a %n" /app/models/* && python -c "from competition.config import *; c=load_submission_config(DEFAULT_CONFIG_PATH, DEFAULT_MODEL_DIR); print([(k, str(v.model_path), str(v.proto_guidance_artifact) if v.proto_guidance_artifact else None) for k,v in c.detector.roles.items()])"'
```

运行时仍由赛事命令传入 `--input` 和 `--output`。不要通过宿主机目录覆盖 `/app/models`，否则会绕过镜像
中已经完成的权限和版本校验。
